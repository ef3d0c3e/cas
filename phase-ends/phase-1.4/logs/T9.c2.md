## Mechanism
- Each `k` rewrite nests the previous form inside `TaylorShift[FractionMod[…]]`; TaylorShift (polytools/two.rs:276) → coefficients/degree/Expand evaluate the nest; parts that warned (FoldLeft "bad argument value", Exponent "not a polynomial in x") are memoised/stamped with warnings (CAS-149).
- Millions of warned hits; `warned_hit` (eval.rs) re-gives each hit's kept warnings (≤ 64) into `Warned::given`, never bounded: instrumented run at 2^22 entries = 3 distinct warnings; gdb: abort in `Eval::warn` push, 1.6 GB realloc. IterationLimit ends the call eventually (~21 s native release+debug-assertions).
- Traced eval (Verbose) of the same input: `Tracer::record` (trace.rs:434) via `close_evaluation`/memo steps grows `Vec<Step>` past malloc_limit (1.2 GB realloc), stack eval_traced ← coefficients ← taylor_shift (addr2line of the replay binary).

## Lessons
- generalizable: a cache hit that replays side data (warnings, trace steps) must be bounded by count, not only the cache's own size: hits are O(1) work so no work limit stops them; anything appended per hit grows with the hit count.
- generalizable: libFuzzer OOM via -malloc_limit_mb = one large realloc; symbolize the replay's stack with `addr2line -f -C -i -e fuzz/target/x86_64-unknown-linux-gnu/release/eval <offsets>`.
