# T9.c1 — eval fuzz: traced RecursionLimit after plain Ok (Fuzz 45285948112, job 138082348286)

## Verdict
Harness, legitimate asymmetry (mirror of a029685). No cas-core change.

## Mechanism
- Plain call (1st on ctx): `IntegrateByPartsU` native evaluates `Integrate[Times[Power[x,-1], …], x]` at depth 2;
  Integrate's algorithm evaluates `D[Power[x,-1], x]` at depth 3 → memoised (it rewrites, so memo only, no stamp);
  the unevaluated Integrate is a fixpoint → stamped. Later, at depth 4, the native meets
  `Integrate[Together[…], x]`, needs `D[Power[x,-1], x]` again → memo hit. Peak depth 16 = limit, Ok.
- Traced call (3rd on ctx, after `ctx.eval(r)`): depth-2 Integrate is an O(1) stamp hit → nothing memoised;
  depth-4 Integrate evaluates `D[Power[x,-1], x]` in full at depth 5; D's rule matcher takes levels via
  `Eval::enter` (eval.rs:471) for its condition tests (`SymbolQ`, `FreeQ`) → `RecursionLimit` at 16.
- Trace level irrelevant; stamp/memo state decides.

## Evidence (scratch crate .run/1.4/t9/repro, C0002/C0005; recursion = 16 from the unit)
- Fresh ctx each: Verbose Ok, Rules Ok, Off Ok.
- Same ctx: plain Ok → plain Err; plain Ok → Off Err → Rules Err; Verbose Ok → plain Ok → Verbose Err.
- Fresh expr rebuilt (interned → same nodes, same stamps) on used ctx: Err.
- `eval_uncached` (no stamps/memo; made pub temporarily): Err(limit) on fresh ctx → cache-free semantics stop too;
  the plain Ok is the cache-assisted outcome.
- Temporary ENTER/LEAVE depth log in `Eval::part` (reverted, `git checkout` of eval.rs): plain run peak 16 with the
  D memoised at depth 3; traced run failing chain IntegrateByPartsU(1) → Together(2) → Times(3) →
  Integrate[Together[…]](4) → D[Power[x,-1],x](5) → matcher levels → 16 ERR; its depth-2 Integrate had no children.
- Engine fix rejected: making limit outcomes cache-independent needs the depth each memo entry/stamp took stored
  and charged on hits — a redesign, not a bug; limits are a stack guard (eval.rs:29-31) and hold either way.

## Change
- fuzz/fuzz_targets/eval.rs:1071-1093: `limit` closure; skip the ok-parity assert when plain Ok and traced is a
  limit error; comment states the mechanism beside the a029685 clause.
