### (a) Design decisions settled by Rationale

Hook (T3, effort high; Rationale 30):
- cas-core's Context (context.rs:47-59) holds an optional printer-and-reader hook: a trait cas-core defines and cas-lang implements over Names, print_with, its parser and lowering. Held behind Arc, Send + Sync like the Context's other shared fields. Set and read through Context methods.
- Offers: input form (print_with, session.rs:180 Balls mode); the forms T4 and T5 add; reading one expression from text.
- Installed by: session (session.rs:131), oracle ours and compare (cas-giac lib.rs:223, :265), fuzz eval target (fuzz/fuzz_targets/eval.rs:884).
- Why: a native gets only the evaluator and its Context (eval.rs:88; C0011); cas-core has no cas-lang dependency; a session arm (with_sqrt call form, session.rs:288) fires only for a whole statement.
- With no hook installed a native leaves the call (Ok(None)). A result printed or read under one hook is never reused under another (cache keyed on state id; state_mut context.rs:394). Random's generator already lives in Context outside State (context.rs:59), the model for the history.
- Its shape is a cross-crate interface that T4-T7 build on; no test arbitrates it.

Markup engine (T4, T5; Rationale 31):
- giac's latex is markup.cc's engine, not tex.cc's: _latex (tex.cc:1468-1486) calls has_improved_latex_export (markup.cc:3779-3797) and keeps gen2tex only for points, algebraic extensions, a few graphic kinds. tex.cc literals disagree with giac in nine places (R1.6-004).
- export_mathml uses the same gen2markup. giac's mathml is mathml.cc's older printer inside an XHTML document (R1.6-005).
- One engine: one MarkupBlock (markup.cc:180-192) carries all three outputs (latex, presentation, content). T4 ports gen2markup into cas-lang (a markup module beside print.rs); latex runs with TOPLEVEL and LATEX flags then prepend_minus (T4 done-when). T5 adds presentation and content outputs to the same block. mathml(e) is a separate module for mathml.cc's printer (T5 files).
- Check: a Python prototype parses giac's own evaluated answers (their input form) and prints by the ported rules; it must match giac on every probe row first (C0009). Same for T5's extension.
- Priorities markup.cc:65-80: a child is parenthesized when its priority is not below its parent's. Negation is a flag (:1777, :972).
- Departures separate printer rules from evaluation: giac evaluates x<y to y>x, ceil(x) to -floor(-x), binomial to factorials, keeps products in input order.

Settings (T6; Rationale 33): where giac applies a setting inside one caseval line, oracle rows; where giac applies it only at its interactive level (approx_mode, autosimplify, eval_level; ans and quest, which caseval answers undef), cas-lang unit tests against giac's documented behaviour plus one departure row each. complex_variables and complex_mode keep our current defaults where they differ from giac's (every existing test relies on them); recorded as departures.

Session (T7; Rationale 34): time and monotonic read the host's clock in cas-lang's session; cas-core keeps no clock (as 1.5 did for limits), so evaluation stays deterministic.

Unicode (T2; Rationale 35): strings are Unicode. Rust strings cannot hold giac's lone bytes (char(233)); counting bytes would cut characters in mid, left and right.

Plus (T2; Rationale 36): "ab"+"cd" stays unevaluated (departure): our Plus is orderless, so "cd"+"ab" would also come out "abcd". cat and concat concatenate.

String and cat printing (T3; Rationale 32): string(e) and cat write our input form, not giac's (our printer spaces sums and lists, giac's does not). Rows compare what the texts read back to; departure is one line. expr reads our language (CAS-DOC-7's one grammar).

DOM_* (T8; Rationale 37): the DOM_* constants are option builtins (symbols with no native, like 1.5's lp_* words), not giac's integers (DOM_INT+0 = 2 is a departure). type(x) == DOM_INT reads the same either way. Giac's other aliases (integer, rational, real, complex, symbol, string, vector, func, float, double, expression, identifier) are not added: most are [types] words (en.txt:842-853) or words LPSolve and NLPSolve match by name (C0008).

TI matrix names (T8; Rationale 38): QR's and LU's TI forms store into their variable arguments (ti89.cc:1970-2025); a native cannot assign (C0011) and our statements are := (CAS-DOC-7 §4), so departures. SVL is svl's alias; SVD is svd's if its answer has giac's layout; LSQ (lsq) and LQ are new builtins over our matrix code.
