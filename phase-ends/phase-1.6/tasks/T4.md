Summary: The engine can now write any expression as LaTeX, the way Xcas does. The printer is a port of giac's own markup code. It was first proved in a Python prototype that matched giac on 301 sample expressions, then written in Rust and fed by a small step that turns our expressions into the shapes giac's printer expects. Where giac and we evaluate the input differently (term order, rewrites giac makes before printing), the oracle tests record both answers as departures.

Decisions:
- binding: T5 extends the same engine (markup/engine.rs MarkupBlock + Flags) with MathML fields and flags; the lowering (markup/lower.rs) is shared; a Form::MathML variant goes through hook.rs like Form::Latex.
- Lowering: Times[-1,y] → neg; negative powers gathered into one inv(den); coefficient ±1/q → denominator (x/2 → \frac{x}{2}); p/q, p≠±1 stays a fraction factor (2/3*x → \frac{2}{3} x); x^(1/2) → sqrt; E^x → exp; balls → giac's %.12g double text; nested equal lists → matrix; Derivative[n][f][x] at a symbol → derive(f(x),x,n); other heads: a Symbol→giac-op table for elementary/special functions, else Names::spelling (our builtins under en.txt names).
- rootof([1,0],[1,0,1,1]) is held in both and prints by the generic function path (giac too: its rootof is symbolic); algebraic extensions and points (tex.cc gen2tex) have no counterpart in ours: README note, no rows.
Deviations:
- The plan listed sqrt(x+1), (x^4-1)/(x^2+3), 2*x^2-3*x+1, 1/(x+1), (x+1)^2, (x+1)*(x-1), sin(x)*cos(x), -(x+1) as agreeing rows; ours evaluates them in another order (constants first, cos before sin) or keeps -(1+x), so they are departure rows with giac's text recorded. The printer prints the same shape the same.
- Extra departure: diff(f(x),x,2) — ours differentiates by x then holds derive(…, 2); giac takes the second derivative. diff(f(x),x,x) is a row instead.
- Two CI rounds of fixes done by the expert (recorded departure texts, a few lines): ce33322, 3c3a984.
Findings:
- Our D[e, x, 2] treats 2 as a variable (held), unlike giac's diff(e,x,n) order form: a candidate ticket for a later phase.
- giac's printer: \frac1{…} only from inv; a product with one integer inv gathers a leading fraction; f(-x,y) drops the minus (giac bug, ported faithfully); trailing spaces (\pi , \infty , \sin , \leq …) are part of the text (proto NOTES quirks 1-12, now in the markup module doc).
Gotchas:
- generalizable: giac's printed answer hides its internal shape (prod(a,inv(b)) vs division both print a/b, different latex); probe latex(quote(typed)) (C0067).
- generalizable: none else; `gen` being a reserved word in Rust 2024 (module named `tree`) is a one-off.
