## Spec corrections (giac probes .run/1.3/T2/probe2-4.out)
- chrem: per-STEP dispatch, not per call: `_ichinrem` takes two integer residues through the integer path (lcm, normalised [0,lcm)), else coefficientwise (m n). After a poly step whose value is an integer, `_ichinrem` normalises it into [0, m n) (chrem([3*x+1,1],[3,5]) = [1,15]).
- modulus 1 is refused ("Bad mod value", is_greater non-strict): chrem([1,2],[1,5]) error; also negative/0.
- one pair returned raw and unchecked: chrem([-12],[5]) = [-12,5], chrem([2],[1]) = [2,1], chrem([x],[5]) = [x,5].
- non-coprime polynomial moduli work (GMP cofactor A, q=(b-a)/d): chrem([x+1,x+3],[4,6]) = [x-3,24]; smod range (-M/2, M/2].
- multivariate residues work (coefficientwise over monomials): chrem([x*y,1],[3,5]) = [-5*y*x+6,15].
- chrem([[R],[M]]) one-matrix form: chrem([[1,2],[3,4]]) = [10,12].
- lgcd: giac fold starts gcd(a1,a1) and stops at 1 (modpoly.cc lgcd): lgcd([-4]) = 4, lgcd([1/2,1/3]) = 1/6, lgcd() = 1, lgcd([-2*x-2]) = -2*x-2 (departure: ours 2*x+2).
- fracmod: nested lists map ([13,[41]]); fracmod(5,1) = 0; complex maps re/im in giac (ours leaves the call, no row).
- icomp: zeros=1 accepted (integer); zeros=x and icomp(5) error.

## Decisions
- giac errors → `refuse` warning, call unevaluated (house convention); departure rows record caseval text verbatim (C0007/C0015).
- Integer chrem steps use cas-num `crt` directly (ChineseRemainder's kernel) so warnings name chrem.
- Poly residues: `Expand`, monomial = term minus leading integer factor; non-integer number coefficient or numeric monomial → "non integer argument".
- bernoulli_mod limit: refuse when p/2 > 1024 · Limits::terms (default allows every p < 2^31; fuzz terms 16..4096 caps at ~4M steps). Not in the brief; C0019 spirit.
- icomp limit: C(n+k-1,k-1)·k > Limits::terms → refuse (C0019).
- fracmod negative m: refuse (libgiac mpz_sqrt of negative); a = 0 → 0 before any check (giac).
- Departures where libgiac crashes (polynomial moduli, bernoulli_mod(2,2)) are ours-only rows; giac is never asked.
