## Notes for the expert
- Behaviour change: a range on a symbol that is not in the objective/constraints now leaves the call (giac errors); before, it added a variable. The fuzz target optimization.rs can hit this when a variable's objective and row coefficients are all 0; it treats a staying call as "past its steps" and returns, so no failure, less coverage.
- Behaviour change: assume=lp_nonnegative with a range below 0 now intersects (giac's) instead of the range replacing the 0 start.
- Ignored-word warnings are only emitted once the program is valid (a call that stays warns nothing).
- fuzz/fuzz_targets/eval.rs BUILTINS not extended (options with no native; not asked).
