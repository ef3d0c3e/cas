# T4.c2 — CAS-605: integer and binary variables in nlpsolve

## Changed
- `crates/cas-core/src/native/optimization/nlpinteger.rs` (new, `mod nlpinteger;` in optimization.rs): `nlp_integer(ev, e, &Program)`.
  - box (checked_mul of range sizes) ≤ `MAX_BOX` 10_000 (pure) / `MAX_MIXED_BOX` 64 (mixed) → lexicographic enumeration, first var most significant; first strict optimum kept.
  - point: constraints free of continuous vars decided exactly (rational sign, else `certain_sign` ball; undecided → skip + warning); pure → objective exact; mixed → sub-`Program` (integers substituted) through `continuous`.
  - else depth-first B&B, `MAX_NODES` 256 ∧ `limits().iterations`, near = 1e-6·(1+|m|), floor branch first, prune when relaxation value certainly ≥ (min) incumbent or equal.
  - warnings: "no integer point is feasible"; node cap (answer or stay); dropped search → "…the answer is local"; root relaxation failure / runaway → stays with today's warning. Interrupt polled per point/node.
- `nlpsolve.rs`:
  - `nlp_solve` body after `program` split into `continuous(ev, &Program) -> Solved {Optimum, Infeasible, Runaway, Failed}`; same warnings as before.
  - `Program` gains `maximum`, `integer`, derives Clone; several items `pub(super)`.
  - `integral()`: binary ends clipped to 0..1, Ceiling/Floor of ends (giac optimization.cc:6861-6876).
  - "not yet" block removed; docs rewritten (lines 18-25).
  - fix: `active()` records side `None` for a one-point range (lo == hi), `optimal()` skips its side check. Before, such a node (common in B&B, e.g. y ∈ [0,0]) failed certification.
- Tests: `optimization/tests.rs` `integer_programs` (13 exact rows, no warnings) and `mixed_and_infeasible_integer_programs`; removed the 4 "not yet" rows from `nonlinear_options_that_stay`.
- Oracle: `cas-giac/tests/nlpsolve.rs` `integer_programs` (giac-answered `(x-1/3)^2` row: ours exactly `[1/9,[x=0]]`, giac within 1e-8); `nlpsolve_seeded.rs` `integer_departures` (9 rows, giac "Failed to find a solution" copied, ours the known optimum at 1e-10). README bullet.
- Fuzz: `integer_nonlinear_program` case in `run()` (now 0..=3), doc comment, fuzz/README row.
