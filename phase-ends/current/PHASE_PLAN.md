## Rationale
- Twelve tasks: the design page, eight build tasks, the push and check pair, the cleanup; at the generation plan's threshold of about 12, so no split now (## Risks says what moves if a task reopens). 37 entries, most of them small; the work is in four places: the distribution object that randvar answers and every later statistics task reads (T2), giac's algorithms whose exact output hinges on its conventions (markov's class search, kmeans' Hartigan-Wong with re-starts, cluster's linkages, kernel_density's bandwidth rule and grid; T4-T6), the sound clip as a value in our expression tree (T7), and resampling with no oracle (T8).
- Order: statistics first, the module that exists, and random variables first within it, since cdf, icdf and mgf take their objects (T3), and kernel_density reads samples while fitdistr answers an object (T5); Markov chains (T4) and clustering (T6) need only lists and matrices. Then the sound clip (T7), which T8's edits take and give; the transforms last (T9): lists only, independent and the most peripheral, so if the phase must split, T9 moves whole, then T6. The tasks run in sequence: all edit en.txt, builtin.rs, native.rs and BUILTINS, and each pushes master.
- Every build task pushes and waits for CI (R16 and the developer's brief): tests run only on CI and rows are written without a local run, so the expert who wrote the code fixes a failure while it holds the context. Build tasks do not wait for Fuzz (about 43 minutes, cancelled by the next push); T10 pushes the final head and T11 waits for both, the shape of 1.3 to 1.6.
- The distribution object (T2, `effort: high`): randvar answers giac's unevaluated law (normald(5.0,1.5), gammad(36,3), binomial(162,1/9), discreted(…)), and sample, randvector, cdf, icdf, mgf, kernel_density's inputs and fitdistr's answer all share it. giac itself treats the parameter-only call as the object (sample(normald(0,1),3) and randvector(3,normald(5,1.5)) draw, probe14.out), and our PDF natives leave such a call, normald(5, 3/2), unevaluated (R1.7-004: read, not run) and print it as giac's; but binomial(n, p) is our binomial coefficient (en.txt:465; the binomial's mass is its three-argument form, :748-749), the discrete laws (weights, [[value, weight]] lists, a density over range=) have no PDF builtin, and a law's name may arrive as another builtin's symbol (normal is Together's, C0008). Which shape the object takes (the parameter-only PDF calls, one new head for every law, or both), how it prints, how sample draws from it and from an expression holding it (giac's find_randvars, vecteur.cc:11215), and how T3 and T5 read it is a cross-task interface that no test arbitrates: one of the two `effort: high` tasks.
- The sound clip (T7, `effort: high`): giac's clip is an opaque C++ object (audio_clip, signalprocessing.h:275) that stores integer codes (16 bit by default) and prints as a one-line description; ours has no opaque value and prints every call as name(args) (print.rs:1347-1392), lang_session asserts that every result the session shows parses and lowers (fuzz/fuzz_targets/lang_session.rs:3, :54-60), and lang_print reads printed forms back (lang_print.rs:23-29, :36-38). Recommended: an internal head over the sample rate, the bit depth and each channel's integer codes, giac's own storage, which keeps every sample exact (k/2^(b-1), R67) and lets channel_data answer from it. The rest is the task's judgment: the head and its storage, how a clip prints in the session, through string() and through the Language hook without breaking those checks, what Plus (orderless, builtin.rs:47: clip1+clip2 cannot keep giac's concatenation order, as 1.6's "ab"+"cd" stayed), Times[-1, clip] (giac's unary minus), ==, size, Part (structure.rs:29 indexes any head's arguments, so clip[0] would not be giac's channel 0) and the evaluator's caching do with it, and its size against Limits::terms (a second of stereo at 44100 Hz is 88,200 codes). T8 builds on that shape and no test arbitrates it: the second `effort: high` task.
- fitdistr: giac divides the sample's sum by N-1 for the mean (optimization.cc:7481, R1.7-005), so fitdistr([1,2,3,4,5],normal) answers normald(3.75,1.78972763291) for data whose mean is 3. That is a slip, not a convention: ours divides by N and keeps giac's other estimators (the variance's N-1, the iterative fits), and every row the slip changes is a departure tested against the prototype's closed form (the generation plan's rule where giac is wrong).
- kmeans draws its starts from giac_rand (Hartigan-Wong with up to 10 re-starts, R1.7-005), so its labels change with the seed (srand(7) relabels probe8.out's answer). Ours draws from the seeded generator; rows compare partitions up to relabelling (labels renumbered by first appearance) on data whose clustering is unambiguous. cluster draws nothing, so its labels are compared as they are.
- resample: giac's Debian build lacks libsamplerate, so every giac row is a departure and the tests check properties: the output length floor(len·rate/sr) of giac's wrapper (signalprocessing.cc:1986), DC kept, a tone inside the passband keeps its frequency and amplitude, a tone above the new Nyquist frequency is attenuated. giac's quality 0 (linear) and 1 (zero-order hold) follow libsamplerate's src_linear.c and src_zoh.c (R1.7-008), exact on exact codes (rational arithmetic, R67); qualities 2-4 (giac's SINC_FASTEST, SINC_MEDIUM, SINC_BEST, :1981-2016) are Smith's bandlimited interpolation with Kaiser-windowed tables of our own, built from the generator parameters libsamplerate's headers record (8, 21 and 69 cycles; increments 128, 491 and 2381; about 100, 122 and 160 dB), not libsamplerate's shipped tables (340,239 coefficients for the best quality, and no generator in its repository).
- dwt follows GSL's wavelet transforms as giac calls them (R1.7-002); GSL is GPL-3 like cas, so T9 ports the filters it needs from GSL's sources. hilbert's list form joins HilbertMatrix's builtin (en.txt:310) as a second argument shape, an integer giving the matrix and a list the analytic signal through our FFT (dft.rs:138's core made reachable, R1.7-006), since giac's hilbert is one name for both.
- about: about(clip) answers as giac's (maple.cc:324); about(x) answers the facts the session's assume recorded for x (context.rs:658 `assumptions()`, R1.7-001) in our form, a departure from giac's internal assume[[],[line[0,+infinity]],[0]] (probe11.out).
- No other `effort: high`: giac's answers, the prototypes and the property tests arbitrate every other done-when.

## Risks
- CI's oracle installs libgiac0t64 from debian:sid unpinned: a giac upgrade mid-phase changes answers in tests nobody touched. Detect: oracle failures outside the task's files, or a version other than 2.0.0.21 in the job log; record it in the task summary and fix the rows or record departures at T11; do not chase it inside a build task. A giac built with libsamplerate would answer resample, and T8's departure rows would then fail and become oracle rows.
- New names collide with words in use: duration, channels, samplerate, bit_depth, bins and bandwidth become builtins, and many of giac's option words are builtins already (## Context, C0008: normal is Together's symbol, binomial the coefficient's; mean, variance, stddev, exact, piecewise, select, matrix, left, right, count, index, type, threshold, limit, residue, extrema, image, normalize, bspline, size); a new builtin can capture a symbol that an existing test uses. Detect: check_round_trip and every_builtin_is_named_or_internal on CI and failures in untouched tests; each task greps en.txt, the lowering and the test suites for its new names first.
- Adding builtins renumbers symbols and moves bloom-filter bits: a `!e.may_contain(S)` assert in an untouched module can flip (C0058); check those first when an untouched test fails.
- Random rows: a property row with too tight a bound fails on CI, and one more draw anywhere shifts every later value under the same seed; bounds are stated in standard errors, rows seed inside their input, and a random row that fails in an untouched test is checked for a changed draw order first (C0014, C0044).
- The distribution object (T2) and the clip (T7) are shapes later tasks build on: if T3, T5 or T8 finds the shape wrong, the fix goes through T2's or T7's module, not a second form beside it; a reopen is T2.1 or T7.1.
- A clip holds up to Limits::terms codes as expression lists: evaluating, hashing, caching and printing such lists can be slow or memory-heavy in the fuzzers (lang_session shows every result; the eval target calls createwav with arbitrary durations); bound before work (C0019), and T11 fixes what Fuzz finds under a regression test.
- giac's hidden conventions: kmeans' and randmarkov's draws (giac_rand), kernel_density's bandwidth rule, emd's sifting and GSL's wavelets were not read by the planner's retrievers (R1.7-002, R1.7-005): a task may find a convention the probes do not pin; the Python prototype settles it before the Rust (C0009).
- resample's sinc qualities have no oracle and our tables differ from libsamplerate's: the property bounds follow from the filter's design, not from observed output, and the module doc states the design so that a later giac built with libsamplerate can be compared.
- The local stable clippy (1.99.1) is older than CI's: CI can flag a lint the local gate passed (R80); fix it in the task.
- A build task reopens twice or the phase passes about 12 tasks: Claude splits the remainder into a new phase through GENERATION_PLAN.md ## Changes at a task boundary (T9 moves whole, then T6).
- libgiac crashes on some inputs and would kill the oracle's test binary: every new oracle input is tried in caseval.py first; a crash becomes a departure with no giac row (C0021; kmeans of a 1-D list crashes).
- GitHub API quota (5000/h) with a CI wait in every build task: one watcher per run at `--interval 60` (C0004); `gh api rate_limit` on a quota warning.
