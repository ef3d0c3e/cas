## Rationale
- CAS-650, guard per native over an inherited budget. R2.1-007: no total budget exists to inherit. `Limits` (context.rs:373) has `recursion`, `iterations`, `match_steps`, `terms`, no step or time counter; `Eval::new` (eval.rs:228-233) resets `iterations` per evaluation, and `Eval::eval_in` (eval.rs:277-296) inherits only the remaining recursion levels, which C0092 tried and rejected (still >120 s). The budget route therefore means a new shared work counter in `Limits`/`Eval`, threaded through `approximation` (numeric.rs:290 takes `&Context`, ~58 call sites in ~45 files) and every native's nested evaluation: a change to the evaluator's core that moves outcomes everywhere (R71: cache-order-dependent limit outcomes already gave fuzz false alarms). The guard is proven twice (LowPass, 1.7/T11, C0092; MarkovChain CAS-649, markov.rs:281) and touches each native once.
- The guard does not cover the plot natives of 2.6: they evaluate a not-yet-numeric user expression at many points, which a guard cannot refuse. Their cost is points times one evaluation, not 2^depth, unless a plot nests in its own argument; 2.6's design page settles their bound (an `is_numeric` guard on the sampled value, plus the interrupt flag checked at eval.rs:745, which 2.4's cancellation can use). The budget route stays open as a later ticket if 2.6 finds it needed.
- T3 covers the remaining `approximation` sites by classification instead of a budget (see Developer decides 1).
- Sweeps: objective value only for lpsolve, because optimal points tie; markov on exact stochastic matrices so answers stay exact (R67) and class order follows giac's Tarjan order (R97).
- Hilbert: a residue rule (split a proper rational function by the half-plane of its poles: H f = i·f_upper − i·f_lower, sign fixed by the row 1/(1+t^2) -> t/(t^2+1)) answers exactly where every pole is found exactly; anything else stays inert as today.
- The euler_lagrange rewrite is one line and CI confirms it, so it rides its own small task with no coder.
- No task is `effort: high`: every done-when is arbitrated by an oracle row, a nesting test or CI.

## Risks
- A guard changes what is refused: a native that approximated a symbolic argument which only becomes numeric under `approximation` (e.g. a held or user-defined constant) now stays unevaluated. Existing oracle rows catch it on CI; the per-native numeric row in T2 guards the common case.
- T3 may find many more nestable sites than expected; past 15 it splits through a plan change.
- Random sweeps find giac quirks (1.8 found about a dozen, R116); each costs a CI round of about 10 minutes plus 45 for Fuzz. giac's markov or lpsolve may abort in the shared process (C0114): the one-process probe comes first.
- The residue rule's exact forms may print differently from giac's (`t/(2*t^2+8)` against `t/(2*(t^2+4))`); `agrees` compares values, but a form mismatch shows as red on CI only.
- The euler_lagrange row may still need the rewrite if giac's spelling is not ours; T6 then keeps it with the evidence.
- The budget route deferred: if 2.6's plot natives need a total evaluation budget after all, it returns as a ticket there, a core change to `Eval`.
