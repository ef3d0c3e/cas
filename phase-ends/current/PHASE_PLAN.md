## Rationale
- Eleven tasks: the design page, seven build tasks, the push and CI-check pair, the cleanup. 72 entries, most of them small; the work is in four designs: a hook from cas-core to cas-lang's printer and reader (T3), one port of giac's markup engine for latex and export_mathml (T4, T5), settings that change evaluation in many natives (T6), and a session that keeps a history (T7). So no split; the risk lines say when to split.
- Build tasks follow code areas, not families, so one expert reads one part of the code: string natives in cas-core (T2); the hook and the commands that need it (T3: string, expr, cat, join's non-string elements); the markup engine with its LaTeX output (T4); its MathML outputs and giac's older mathml (T5); the settings (T6: State, lower.rs, session.rs, the natives they change, the printers for increasing_power); the session commands (T7: session.rs and a history the Context carries); area 18's names (T8: cas-core natives beside existing builtins). Strings come first, the base of every text answer; the hook before the printers, which are natives reaching cas-lang through it; LaTeX before MathML, since giac builds both in one MarkupBlock (markup.cc:180-192), so T4 ports the engine and T5 adds outputs; settings after the printers, since increasing_power changes all of them; session commands after the settings, since restart resets them; area 18's names last: independent and the most peripheral, so if the phase must split, they move whole. The tasks run in sequence: all edit en.txt, builtin.rs, native.rs and BUILTINS, and each pushes master.
- Every build task pushes and waits for CI (R16 and the developer's brief): tests run only on CI and rows are written without a local run, so the expert who wrote the code fixes a failure while it holds the context. Build tasks do not wait for Fuzz (40 minutes, cancelled by the next push); T9 pushes the final head and T10 waits for both, 1.3's to 1.5's shape.
- The hook (T3, `effort: high`): string, expr, cat, latex and mathml must print or read from inside evaluation (size(string(x+1)), latex inside a user function), but a native gets only the evaluator and its Context (eval.rs:88; C0011) and cas-core has no cas-lang dependency. A session arm (the with_sqrt call form, session.rs:288) fires only for a whole statement, so it cannot serve them. A trait object in the Context, installed by cas-lang, can: the Context is Clone over Arcs (context.rs:47-59), and the random generator already lives there outside State. Its shape (which crate defines what, how caching treats it, who installs it: the session, the oracle's ours and compare, the fuzz eval target) is a cross-crate interface that T4 to T7 build on and that no test arbitrates: the one `effort: high` task.
- giac's latex is markup.cc's engine, not tex.cc's: `_latex` (tex.cc:1468-1486) calls has_improved_latex_export (markup.cc:3779-3797) and keeps gen2tex only for points, algebraic extensions and a few graphic kinds; tex.cc's literals disagree with giac's answers in nine places (R1.6-004). export_mathml uses the same gen2markup; giac's mathml is mathml.cc's older printer inside an XHTML document (R1.6-005). So the port follows markup.cc, checked by a Python prototype that prints giac's own evaluated answers by the ported rules and matches giac's text on every probe row. That separates printer rules from evaluation differences (giac evaluates x<y to y>x, ceil(x) to -floor(-x), binomial to factorials, and keeps products in input order), which become departure rows that name the evaluation, not the printer.
- string(e) and cat write our input form, not giac's: our printer spaces sums and lists, giac's does not. Copying giac's spacing would fork the printer for no difference in value; the rows compare what the texts read back to, and the departure is one line. expr reads our language (CAS-DOC-7's one grammar): giac's expr("0123") = 83 (octal) and expr("a:=3") (an assignment, which a native cannot make, C0011) are departures.
- Settings: where giac's library applies a setting inside one caseval line (complex_mode, angle_radian, increasing_power, epsilon, the gbasis words, cas_setup's layout), oracle rows; where giac applies it only at its interactive level (approx_mode, autosimplify, eval_level, and ans and quest, which caseval answers undef), cas-lang unit tests against giac's documented behaviour plus one departure row each. complex_variables and complex_mode keep our current defaults where they differ from giac's (every existing test relies on them), recorded as departures.
- Clocks: time and monotonic read the host's clock in cas-lang's session; cas-core keeps no clock, as 1.5 decided for limits, so evaluation stays deterministic.
- Strings are Unicode: Rust strings cannot hold giac's lone bytes (char(233)), and counting bytes would cut characters in mid, left and right.
- "ab"+"cd": giac concatenates; our Plus is orderless, so "cd"+"ab" would also come out "abcd": the + form stays unevaluated (a departure); cat and concat concatenate.
- The DOM_* constants are option builtins (symbols with no native, like 1.5's lp_* words), not giac's integers (DOM_INT+0 = 2 is a departure): `type(x) == DOM_INT` reads the same either way. giac's other aliases for them (integer, rational, real, complex, symbol, string, vector, func, float, double, expression, identifier) are not added: most are [types] words (en.txt:842-853) or words LPSolve and NLPSolve match by name, which an alias would capture (C0008).
- QR's and LU's TI forms store into their variable arguments (ti89.cc:1970-2025): a native cannot assign (C0011) and our statements are `:=` (CAS-DOC-7 §4), so they are departures. SVL is svl's alias, SVD svd's if its answer has giac's layout, and LSQ (lsq) and LQ are new builtins over our matrix code.
- No other `effort: high`: giac's answers, the prototypes and the unit tests arbitrate every other done-when.

## Risks
- CI's oracle installs libgiac0t64 from debian:sid unpinned: a giac upgrade mid-phase changes answers in tests nobody touched, the printers' exact text most of all. Detect: oracle failures outside the task's files, or a version other than 2.0.0.21 in the job log; record it in the task summary and fix the rows or record departures at T10; do not chase it inside a build task.
- New names collide with words in use: `string` is a [types] word (en.txt:851) and becomes the command's name; aliases for the DOM_* constants would capture [types] words and words the solvers match by name (C0008); left, right, type, time, version, join, split, trim and char may be symbols in existing tests or option words some native matches by name. Detect: check_round_trip and every_builtin_is_named_or_internal on CI (names/tests.rs:91, :135) and failures in untouched tests; each task greps en.txt, the lowering and the test suites for its new names first.
- Adding builtins renumbers symbols and moves bloom-filter bits: a `!e.may_contain(S)` assert in an untouched module can flip (C0058, 1.5/T4); check those first when an untouched test fails.
- The hook makes printing and reading reachable from evaluation and from the eval fuzzer: deep or huge expressions, long strings and adversarial texts (the parser's depth history: CAS-162, CAS-163, CAS-168) can hang or overflow the stack; bounds before work (C0019), and T10 fixes what Fuzz finds under a regression test.
- Caching: a result that depends on the hook, a setting or the history (string, latex, ans, trig under angle_radian) must not be reused where they differ: settings go through state_mut (a new state id, C0011); the hook and the history do not, so T3 and T7 read the cache path first.
- giac's printed text depends on giac's evaluation (term order, rewrites; ## Rationale): a printer row can fail for an evaluation reason; the Python prototype separates the two, and such rows become evaluation departures, not printer changes.
- markup.cc's gen2markup interleaves LaTeX, MathML and Scheme over about 2,400 lines (R1.6-001 estimates a 1,100-1,500-line Rust port): T4 may outgrow one context; hand off by TASK_PROGRESS.md and the respawn keeps the task id; a coder that hands off writes logs/T<n>.c<k>.progress.md (R68).
- Settings reach many natives (angle_radian every trig native and its inverse, complex_mode solve and factor, increasing_power every printer): T6 may outgrow one context; if it reopens, Claude splits family (8) into its own task through ## Changes.
- The local stable clippy (1.99.1) is older than CI's: CI can flag a lint the local gate passed (1.5/T4); fix it in the task.
- A build task reopens twice or the phase passes about 12 tasks: Claude splits the remainder into a new phase through GENERATION_PLAN.md ## Changes at a task boundary (T8 moves whole, then T7).
- libgiac crashes on some inputs and would kill the oracle's test binary: every new oracle input is tried in caseval.py first; a crash becomes a departure with no giac row.
