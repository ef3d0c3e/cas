## Rationale
- Ten tasks: the design page, six build tasks, the push and CI-check pair, the cleanup. 41 names in 21 aide entries is half of 1.3's 81, but the work sits in ports more than in names (Romberg and gauss15's budget, newton's iteration, ratinterp's default, the B-spline knots, fitpoly's degree rule, the MODI tie-breaks, Remez), so no split.
- Build tasks follow code areas, not families, so one expert reads one part of the code: quadrature (nintegrate's neighbourhood), solvers (fsolve, a certified Newton, convert), exact sampling and interpolation (interpolation.rs, dft.rs), splines and least squares (regression's normal equations, the Chebyshev nodes), the transportation simplex (optimization/), Remez. Quadrature first: one command and twelve options settle the phase's ball-against-giac-float rows. Then the solvers (mostly existing code), the small exact names, the fits, tpsolve, and minimax last: it reuses the earlier pieces (ball evaluation of f, a bracketing root finder for the extrema, Chebyshev nodes, linear solves) and its convergence is the phase's largest unknown; if the phase must split, minimax moves whole. They run in sequence (each depends on the one before): all edit en.txt, builtin.rs, native.rs and BUILTINS, and each pushes master.
- Every build task pushes and waits for CI (R16 and the developer's brief): tests run only on CI and the rows are written without a local run, so the expert who wrote the code fixes a failure while it holds the context. Build tasks do not wait for Fuzz (40 minutes, cancelled by the next push); T8 pushes the final head and T9 waits for both, 1.3's shape.
- Certification follows what each answer claims (## Context, Numbers): a fixed rule's answer is its sum, so the ball holds the exact sum, not the integral; gauss15 is giac's adaptive integrator (evalf_int, R1.4-004), so ours certifies the integral through NIntegrate's Gauss–Legendre panels and giac's [estimate, sum] pairs for n ≤ 3 are departures; a newton that converged claims a root and certifies it, one stopped by its iteration count returns giac's iterate; minimax's error is a ball around max|f-p| for the p it returns.
- minimax converges further than giac: giac stops once its levelled errors agree within 2% (R1.4-003), which leaves minimax(exp(x),x=0..1,1) at 0.106657010751 where the best error is 0.1059334; ours tests closed forms and accepts giac's numbers within its 2%. giac's minimax(abs(x),x=-1..1,2) is not the best approximation (x^2+1/8, error 1/8, alternating at -1, -1/2, 0, 1/2, 1): a departure.
- The twelve solver names become en.txt names (options, as 1.2's plex and rur): the gap accounting reads en.txt, and FSolve then matches builtin symbols, groebner.rs:251's way, instead of a user symbol's name.
- tpsolve stays here, as the generation plan scopes R0-004 area 15, though it is an optimisation: it is self-contained (MODI over exact rationals, checked against LPSolve) and 1.5 already carries area 14's 51 entries. linspace joins: R0-004 put it in no area, it is this module's sampler and fitspline's examples use it. LSQ stays with 1.6 (R0-004 area 18).
- No `effort: high`: giac's numbers, closed forms, equioscillation and LPSolve arbitrate every done-when.
