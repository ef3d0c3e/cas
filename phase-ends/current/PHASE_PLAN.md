## Rationale
- Twelve tasks: the design page, eight build tasks, the push and CI-check pair, the cleanup. R1.3-007 found about 78 buildable entries; ## Context builds 81 (copy, multiply, groupermu and compare from its unclassified list; multinomial and the infix operators out). That is 1.2's size (89 entries, 12 tasks), so no split.
- Build tasks follow code areas, not Lific modules, so one expert reads one part of the code: number theory, lists, expression rewriting, expression structure and predicates, calculus tools, the function study (domain, then signs, then variations and convexity, the chain giac's tabvar computes), Kovacic, Risch. Integers, lists and expressions first: many small names settle the per-name pattern and the CI rhythm. The three ports last (T7 tabvar, T8 Kovacic, T9 Risch), Risch the very last: its departure-and-backlog fallback can end it early, and if the phase must split it moves whole. They run in sequence (each depends on the one before): all edit en.txt, builtin.rs, native.rs and BUILTINS, and each pushes master.
- Every build task pushes and waits for CI (R16 and the developer's brief): tests run only on CI and about 80 names get oracle tests written without a local run, so the expert who wrote the code fixes a failure while it holds the context. Build tasks do not wait for Fuzz (40 minutes, cancelled by the next push); T10 pushes the final head and T11 waits for both, 1.2's shape.
- Ports where giac's output follows its own conventions (tabvar's reductions and strings, risch's tower and Ei, Kovacic's cases, PARI's certificate witnesses): 1.2's T4 and T9 matched giac exactly this way (R30, C0009), where probes alone left the formula open.
- risch sits beside Integrate, not in it: the generation plan scopes it so, and putting it into the pipeline would change answers across the integrals*.rs oracle files and the departures of CAS-DOC-9, 40 and 49, a decision for a later phase.
- is_prime proves its answers: the deterministic test below 2^64, the n−1 test above. APRCL, which giac reaches through PARI, is a larger algorithm and becomes a backlog ticket; an unproved prime is never answered 1.
- The infix operators are grammar: giac 2.0.0's prefix calls fail (union, intersect, div) or misprint (xor), so no oracle row could agree, and CAS-DOC-7's one grammar stands. multinomial is a distribution (Statistics, 1.7). changebase, semi_augment and divis belong to 1.2's modules: 1.8's gap accounting takes them rather than widening this phase.
- The list commands file in Evaluator: CAS-DOC-28's list operations (CAS-PLAN-22) are all there, so no new module is needed.
- The Abs fix rides T2 (the developer's optional chore, R34): R1.3-003 shows it local (clamp re²+im² at 0 before the square root, as Arb's arb_sqrtpos) with one unit test, and T2's push and CI wait surface any test that relied on the indeterminate answer.
- `effort: high` on T9 only: whether the port decides elementary integrability correctly is a judgment no test arbitrates (an unevaluated answer agrees with giac's unevaluated one whether or not the decision was right). The other ports are arbitrated by giac's exact output (T7) and by substitution into the equation (T8).

## Risks
- CI's oracle installs libgiac0t64 from debian:sid unpinned: a giac upgrade mid-phase changes answers in tests nobody touched. Detect: oracle failures outside the task's files, or a version other than 2.0.0.21 in the job log; record it in the task summary and fix the rows or record departures at T11; do not chase it inside a build task.
- libgiac crashes on some inputs (heappop of a literal list, chrem with polynomial moduli) and would kill the oracle's test binary: every new oracle input is tried in caseval.py first, and a crash becomes a departure with no giac row.
- giac quirks in its own examples (simplifyDirac's series(…) answer, epsilon2zero's 0+x+5, wz_certificate's 0 on its fourth example, the infix-only operators): test where giac answers sensibly, record the rest as departures.

- is_prime cannot prove every prime giac proves (giac reaches APRCL through PARI): the rest stays unevaluated with a warning and a departure row; APRCL is a backlog ticket.
