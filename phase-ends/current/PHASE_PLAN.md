## Rationale
- Twelve tasks: the design page, eight build tasks, the push and CI-check pair, the cleanup. R1.2-006 counted 89 entries, inside the generation plan's estimate (about 100); twelve tasks sit at its "about 12" split threshold, so no split.
- Build tasks follow code areas, not Lific modules, so one expert reads one part of the code: gcd (cas-poly gcd), fractions and convert (polytools, bits), real and listed roots (cas-poly sturm, cas-num ball roots), complex solving and settings (solve, context), polynomial tools, Gröbner (cas-poly groebner), matrix utilities (many names, mechanical), elimination and canonical forms (fewer names, real algorithms). Polynomial work first, matrices last. They run in sequence (each depends on the one before): all edit en.txt, builtin.rs, native.rs and BUILTINS, and each pushes master.
- T1 first: the generation plan opens each area with its page, and every commit names a ticket, so the tickets exist before the code.
- Every build task pushes and waits for CI: tests run only on CI, and about 65 new commands get oracle tests written without a local run, so a failure is fixed by the expert who wrote the code while it holds the context. R16 lets agents push whenever CI needs to run. Build tasks do not wait for Fuzz (40 minutes, cancelled by the next push); T10 pushes the final head and T11 waits for both, the developer's push-then-check shape without a review stop.
- Inert forms are departures: giac itself only holds them, ours already leaves a capitalised call unevaluated, and an alias would evaluate where giac holds. Engine knobs are departures: they tune an engine ours does not have. increasing_power is printing, 1.6's subject.
- all_trig_solutions and with_sqrt follow the Digits precedent (R1.2-005), not a general settings mechanism: 1.6 owns the session and settings commands, and two flags do not justify a framework now. with_sqrt defaults to 1 as in giac: our factor already splits quadratics over sqrt (polynomials.rs:168), so the new behaviour is with_sqrt(0).
- rur gets a fallback (a recorded departure plus a backlog ticket): the zero-dimensional machinery (normal set, multiplication matrices) is absent (R1.2-003), and one option should not block the phase.
- Local giac lookups read the reference, the same build as CI's, so the CI-only test rule holds and the expected answers are known before the push.
- No `effort: high`: every done-when is arbitrated by CI's oracle and unit tests, and the judgment calls (inert forms, knobs, settings) are settled here.
