## Rationale
- Order: T1 first, because random_n_deriv fails at random (CI 46005114300, 46037332695) and would turn any later task's CI red. T2 settles the API before code. The line index (T3) is the first query and creates the fuzz target the later tasks extend. T4 pins the half-typed trees the cursor (T5) and symbol (T6) queries read. The doc table (T7) comes last because the fuzz target reaches it through the cursor's name.
- T2 is `effort: high`: its done-when rests on judgments no test arbitrates, namely the query API that 2.3 translates to the protocol (types, names, what a cursor context and a symbol are) and the static scoping model. Every later task is arbitrated by unit tests, proptests, the differential test against lowering or the fuzz target.
- The symbol index is its own error-tolerant walk over the tree, not a table recorded by lowering. Lowering skips every statement with a syntax error (lower.rs:292-302), and that is the statement an editor is typing; it also scopes while it builds `Expr`s (about 650 of 2100 lines, R2.2-004). The walk reuses lowering's tree helpers that need no `&mut self` and copies the block rule (locals = assigned names minus reserved names and parameters, lower.rs:1447-1452). A differential test pins it to lowering on error-free text, so drift shows on CI.
- Fixes on lexer and parser errors use lowering's `Fix` (lower.rs:144), so 2.3 turns every fix into a quick fix the same way, and `Session::run` passes them to `Message.fix` (parse errors get `fix: None` today, session.rs:276).
- Recovery: inside brackets a line break does not end a statement (README.md:12), so a half-typed `f(x, ` may absorb the complete statements below it. T4 tests that case first; recovery is tightened only where a test shows a following statement lost, and the trees of error-free text never change.
- Doc table: a Python generator beside scripts/aide.py (giac lookups are Python scripts here, and CI has no aide_cas) writes a line-record text file beside names/en.txt, embedded with `include_str!` as en.txt is (names.rs:27) and read once. It is keyed by builtin target, so aliases share one entry and `::` types stay a namespace of their own. Not generated Rust: fmt and clippy would check it and its diffs read worse. aide.py's `entries()` is lossy (it drops related names, and an example starting `2 ` overwrites the English line, R2.2-001), so the generator and aide.py share one positional reader. 817 of the 826 [builtins] targets have a giac entry (planner's count, 2026-11-28); the overlay covers the other 9. Examples our parser rejects (giac-only syntax) are not shown, dropped when the table loads; T2 may choose marking them instead.
- Licence: aide_cas is GPL-3+ (Debian's copyright file, /usr/share/doc/libgiac0t64/copyright:184-190; R0-004), usable under our GPL-3.0-only (README.md:30-32). The generated file's header names its source (xcas 2.0.0.21+dfsg2-3+b1, sha1 25558508ea0e2d5eaa6b7dbb8d985727dd84f030), the five authors and the licence, and says it is extracted and changed (GPL-3 §5a); the crate README credits the authors. That source version is CI's pinned oracle version, so 2.2 does not depend on I4: a move reruns the generator.
- One fuzz target, `lang_analysis`, created by T3 and extended by T4-T7, so each query is fuzzed from the push that adds it.
