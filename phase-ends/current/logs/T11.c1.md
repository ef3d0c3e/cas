# T11.c1 — CAS-650: own-head nesting guard (depth >= 2)

## Changed (commit 99abffd)
- `crates/cas-core/src/native.rs`: `pub(crate) fn holds_nested(e, head: Symbol) -> bool` + private `holds_call`; explicit-stack walk, `seen` set (FixedState, as traverse.rs), `e.contains(head)` prefilter. True when a call of `head` has an argument holding another call of `head`.
- Guards, `Ok(None)` when true:
  - `solve/fsolve.rs` `fsolve`: on `f`, before `numeric` (FSOLVE).
  - `solve/fsolve/systems.rs` `system`: on each `fs`, before `numeric` (FSOLVE).
  - `solve/fsolve/complex.rs` `cfsolve`: on each `fs`, before `numeric` (CFSOLVE).
  - `optimization/nlpsolve.rs` `nlp_solve`: on every arg of `e`, at entry. Deviation: entry, not after `program`, because `program`'s `bounds`/`as_bound` already call `double` → `approximation` (NLP_SOLVE).
  - `integrate/definite.rs` `integral`: on `f`, beside the existing antiderivative-holds-`Integrate` check (INTEGRATE).
- Module doc line "CAS-650: a function holding a nested own-head call (depth >= 2) leaves the call." in all five.
- Tests (2 per native):
  - solve/tests.rs: helper `nested_own_head`; `nested_fsolve_function`, `fsolve_in_fsolve`, `nested_fsolve_system`, `fsolve_in_fsolve_system`, `nested_cfsolve_function`, `cfsolve_in_cfsolve`.
  - optimization/tests.rs: `nested_nlp_lower_bound`, `nlp_in_nlp`.
  - integrate/tests.rs: `nested_integrand`, `integrate_in_integrate`.
- Depth-1 tests use an inner call that evaluates first (FSolve[y-2,y] → 2; Part[CFSolve[y-1,y],1]; Part[NLPSolve[y²+1, y∈[1,3]],1] → 2; ∫y 0..1 → 1/2), expected by hand: √2, i (from 1+i), 4 at x=2, 1. A held depth-1 inner call cannot answer in these natives today (numeric approximation turns sample rationals into balls; Newton needs D of the held call; Integrate's antiderivative check). So the FSolve and Integrate depth-1 tests also assert `holds_nested` false on a held depth-1 shape and true on depth 2.
