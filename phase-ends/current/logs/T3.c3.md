# T3.c3 — CAS-627 logistic_regression CI fixes (CI run 45584193534)
## Causes
- Unit tests: full-form reader has no decimals (C0047) → `Logistic[0.5]`, `6.24947835314` etc. failed to parse.
- Root cause of both oracle failures: `line` (regression.rs) wrapped the slope in `Together`; `Together` refuses non-exact data (`polynomial::together` → `convert` → None), so a ball slope stayed `Together[Ball]`.
  - Exact rows: 2nd fit (times vs ball logs) → `b2 = Together[Ball]`, `bt0 = Expand[ȳ − 2·b2]` = `Ball + Times[-2, Together[Ball]]`; exponent and entry 5 kept the residue; oracle `close` (tail_probabilities.rs:54) evaluates `N[·,30]` of the difference, `Together[Ball]` never becomes a number → `Less` not True → check_entries (:479) fails.
  - Decimal rows: 1st fit (C vs w/C, balls) → slope `Together[Ball]` → `real_sign` None → degenerate branch → 5× Indeterminate; r (Correlation) unaffected, hence the lone ball.
## Changed
- regression.rs `line`: slope = eval(sxy/sxx); `Together` only when not `View::Ball` (exact path unchanged: Together of the evaluated quotient = Together of the unevaluated one). Doc on `line` + module doc ("balls for decimal data"). Also affects linear/exponential/logarithmic/power regression on ball data (residue removed; no existing decimal rows for them).
- statistics/tests.rs: decimals → hex floats (0.5→0x1p-1, 3.5→0x1.cp+1, 4.5→0x1.2p+2, 1.0→0x1p+0, 0.0→0x0p+0, expected values = float.hex of the old decimals). Intent unchanged.
