# T6.c3 — CAS-618: increasing_power in every printer

## Change
- `crates/cas-lang/src/print.rs`: new pub `power_order(e, increasing) -> Cow<Expr>` (re-exported in lib.rs): flag off → every
  `Plus` whose terms are all `c*v^k` (one user symbol v, c a number atom, k Int >= 0; number = degree 0; at least one term
  with v) stable-sorted by decreasing degree, at every level (head and args). Flag on → `e` unchanged (Borrowed): canonical
  order already ascends, so flag-1 output is byte-identical by construction. Depth > MAX_PRINT_DEPTH → unchanged.
  Builtin symbols (pi) are not v; negative powers, Times with two symbols → sum keeps order.
- `hook.rs` `Hook::print`: `power_order(e, ctx.increasing_power() || size > max_len)` before every form
  (Input/Latex/Mathml*/MathmlDocument). Size guard: printers refuse those anyway; avoids walking huge trees.
- `session.rs`: new private `text()` = power_order(self.context flag) + print_with; used by `show` and `written`.
- Module docs: print.rs, markup.rs, mathml.rs, hook.rs, lib.rs (giac gen.cc :10081-10109, :10094).
- Public signatures of print/print_with/latex/export_mathml/mathml unchanged.

## Deviation from brief rule
- Flag 1 does not re-sort (identity), rather than a stable ascending sort: our evaluated sums already ascend; an unevaluated
  sum keeps its order with flag 1, as giac's (probe3: `x^3+2x+1` stays with 1). Flag 0 does reorder unevaluated input too.
