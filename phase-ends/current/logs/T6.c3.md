## Cause (evidence: temporary eprintln in Eval::evaluate, reverted; `.run/1.8/t6/dbg1.log`)
- The rule's PatternTest evaluates `IntegerQ[arg]` on held args, so evaluating nested `k` costs about 9 levels per
  nesting (matcher nodes + test eval): r from scratch enters at depths 1 -> 10 -> 19 -> 28 (`k[0, 0, h[...]]`), and the matcher passes 34.
- eval(e) finished only because, at depth 19, `k[0, 0, h[...]]` was a "warned hit" in the per-call warned memo
  (NoDefinitionMatches); eval(r) is a new call, so that memo is gone and the part was never stamped
  (memoise_warned, eval.rs ~655-665: a part that warned only in its own rewrites is not stamped, "evaluated again where it
  is met, it takes one level"). Here re-evaluating it takes ~9 levels, not one.
- Controlled check: caches gated off by a temporary env var, eval(e) itself = Err(RecursionLimit); with caches, Ok.
  So the input exceeds the limit on its own; caches hid that in eval(e) and not in eval(r). It is the same class as the
  harness's existing tolerance at fuzz/fuzz_targets/eval.rs:1260-1265 ("Without caches the input stops there too").

## Options (for the expert)
1. Harness (fuzz/): tolerate a limit error (Recursion/Iteration/Match) on the idempotence re-evaluation, with a comment
   naming this mechanism. This loosens the check, which the brief excluded, but C0043 says harness first and the
   harness already tolerates this class between plain and traced runs.
2. Engine (cas-core eval.rs memoise_warned): stamp a warned fixpoint whose evaluation went deeper than one level.
   Nearly every NoDefinitionMatches part enters the matcher, so this would stamp almost all of them. That reverses
   the cost trade-off in CAS-149 (ebc448c) and fills the MAX_WARNED table. It is a design decision, not a local fix.
- Recommendation: option 1, unless CAS-149's trade-off is to be revisited.
