Summary: An editor can now ask what is under the cursor at any position: which token, whether a name or a type after `::` is being typed (with the span a completion would replace), whether the cursor is in a string, a comment or a number, and which call it is inside and at which argument, even in unfinished input such as `f(x, ` or `sin(`. The fuzzer checks the query at every sampled position of arbitrary text. The fuzz job for it was moved to the faster configuration so it fits its time limit.

Decisions:
- Tokens found by `covering_element` on a one-byte range plus `prev_token`, not rowan's `token_at_offset` (linear per level).
- Unterminated string/comment detected from `parse.errors()` (UnterminatedString/UnterminatedComment ending at len).
- Call = innermost qualifying ArgList among ancestors of the left, right and last significant token; per-query cost O(depth + trailing trivia run).
- lang_analysis fuzzes without ASan: crates are `unsafe_code = "deny"`; rowan under ASan stays covered by lang_parse/lang_lower/lang_print.
Deviations:
- §3's "ArgList whose `)` is missing" read as reaching only to the next significant token after it (else every later line would be inside the call): with lines below, `f(x, ` covers up to and including the start of `y`, outside from the end of `y`.
- `String`/`Comment` only when strictly inside, unterminated, or a line comment; a closed string/comment at its own start or end is an empty spot (§3 says "inside").
- Fuzz cursor offsets: §7's ≤1024 sampled boundaries plus inner bytes of the first 64 multi-byte chars, `len+1`, `usize::MAX` (c1 also ran 1024 raw spaced offsets; dropped for the job budget).
- fuzz.yml edited, outside the task's file list, to meet the done-when's "Fuzz run completed".
Findings:
