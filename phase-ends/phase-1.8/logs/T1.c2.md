# T1.c2 — CAS-638: integrate_two recursion limit (zero denominator)

Finding: Fuzz 45734501868 job 139624467152, integrate_two, "recursion limit exceeded" on
`Integrate[tan(1+x)(3+3cs-3s²)/(3-3c²-3s²), x]` (denominator identically 0).

## D/nth (CAS-636) not involved
- Integrator builds only 2-arg `D[g, x]`: risch.rs:807, definite.rs:280/804, heuristics.rs:184/285,
  rationalise.rs:104/344 (grep `Symbol::D` in native/integrate*). D/nth (calculus.rs:357-361) matches 3 args only.
- No 3-arg `D[...]` literal in cas-core src outside calculus.rs rules.

## Cause (by reading; R74, no local run)
- rationalise.rs `trigonometric`: Bioche F(-s,-c)=F → Rule::Tangent; c=1/√(1+u²), s=u c → denominator
  `3 - 3/(1+u²) - 3u²/(1+u²)`; `Together[r]` → conversion DivisionByZero (polynomial.rs `refused`) → held `Together[r]`.
- rational_integral → integral_at depth 1 → heuristics `substitution`: `Together[f/derivative]` with f = `Together[r]`.
- polynomial.rs `inside` (reach_inside, P6) wrapped the held `Together[X]`'s arg: `Together[Together[X]]`; its eval
  calls together → reach_inside → `Together[Together[X]]` again → unbounded nested eval → Limits::recursion (512).
  Same loop for `Expand[Expand[X]]` when Expand refuses.
