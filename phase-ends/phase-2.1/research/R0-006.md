## Answer

(a) Framework pick. No source settles the choice; these are the facts found plus a reasoned recommendation.
- lsp-server (rust-analyzer family, synchronous, crossbeam channels) gives the most control over a dispatch loop. Long evaluations can run on worker threads with a shared interrupt flag wired to cas-core's interrupt, and you own the $/cancelRequest bookkeeping. This is the best fit for off-loop CAS evaluation, but the docs page did not confirm a cancel helper, a request queue API, or Connection::memory().
- tower-lsp-server 0.23.0 (community fork, released 2025-12-07) is the maintained async option with LspService. Its docs do not mention cancellation or in-process test helpers. Original tower-lsp appears stalled (last commit Jan 2024 per a blog, Oct 2025).
- async-lsp 0.2.4 (released 2026-04-24) is tower-based, with concurrency via tower Layers and lsp-types ^0.95. It is young (0.2.x), and its docs show no cancellation or test helpers.
- lsp-types 0.97.0 (docs.rs, dated 2024-06-04) targets LSP 3.16 stable; 3.17 and 3.18 items sit behind the `proposed` feature. Verify against the crate you pick, since fork crates (ls-types, lsp-types-max) claim newer coverage that was not verified.
- Position encoding (utf-8 vs utf-16) is negotiated in 3.17 (general.positionEncodings client, positionEncoding server); not re-verified this session.
- Pull diagnostics (diagnosticProvider, workspace/diagnostic) and inlay hints are 3.17 items; notebook document sync is 3.17; the 3.18 spec marks notebook filter types, code lens resolveSupport, and inline completion as @since 3.18.
- Semantic tokens: full, range, and delta are present in the protocol; whether "Full Delta" is 3.16 or 3.18 is unresolved (one third-party doc says 3.18.0; not verified).
(b) Highlighting. Zed: semantic_tokens off|combined|full (default off). Neovim 0.12.0 (released 2026-03-29) adds multiline semantic tokens. Helix: no semantic-token docs found; treat as tree-sitter-only. Emacs eglot/lsp-mode, Kate, Sublime LSP, CodeMirror 6: NOT FOUND for 2026 status.
- TextMate test: vscode-tmgrammar-test 0.1.3 (unit tests plus vscode-tmgrammar-snap snapshots), reportedly superseded by textmate-grammar-test (maintenance not verified).
- tree-sitter test: corpus tests in test/corpus, `tree-sitter test`, `-i` to filter, `-u` to update. Highlight-assertion testing not verified.
- VS Code: @vscode/test-cli + @vscode/test-electron (runTests, launchArgs); the page does not cover xvfb; CLI runs fail if another VS Code instance is open.
- Neovim headless smoke test: not researched.
(c) Result display. Lean 4 uses custom $/lean/ methods: $/lean/plainGoal, $/lean/plainTermGoal, $/lean/rpc/connect, $/lean/rpc/call, $/lean/rpc/keepAlive (about every 10s), $/lean/fileProgress. Julia and Wolfram/CAS servers: NOT FOUND.
- Notebook sync, inlay hints, code lenses: standard 3.17 (notebook, inlay hints) and 3.18 (code lens resolve) features; editor support varies and was not checked.

Recommendation (reasoned, not sourced): start with lsp-server for the evaluation loop, or tower-lsp-server if async handlers matter more; in either case verify $/cancelRequest handling in the chosen crate's source before committing. Test in-process with the framework's in-memory transport if it exists; otherwise a stdio test of the built binary on GitHub Actions.
