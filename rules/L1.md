# L1 — CAS features before kernel speedups; no new unsafe
id: L1 · group: - · status: active · tags: priorities,unsafe,scope · origin: gen3.2 memory focus-on-cas-features.md · added: 2026-11-22

## Text

Work on what the CAS can do: features, builtins, algorithms the language exposes, correctness, giac/Xcas parity.
Low-level kernel speedups are optional and deferred: CAS-30 (SIMD/assembly multiplication kernels, needs `unsafe`)
stays in the backlog until it becomes a requirement. The workspace keeps `unsafe_code = "deny"` (`Cargo.toml`);
the one exemption is cas-giac's loader `crates/cas-giac/src/library.rs`. New `unsafe` needs the developer's word.

Why: the developer, 2026-10-25: "Skip it, CAS-30 is completely optional, we'll do it later if it becomes a
requirement, right now focus on the CAS itself."
