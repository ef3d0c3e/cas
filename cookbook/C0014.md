# giac oracle answers that depend on random state: seed inside the same input

giac's shared instance (`Giac::shared`) serves a whole test binary whose tests run in parallel threads, so a giac
command that draws random numbers (`nlpsolve`'s starting points) answers differently with the test order: the same
commit passed once and failed twice on CI (`nlpsolve(x^2+y^2,[x+y=1],maximize=false)`: "Failed to find a solution").

- Diagnose locally: feed giac the binary's inputs in shuffled orders (`shuf inputs.txt > o.cas; giac < o.cas`, 15-25
  runs) and count the answers of the suspect line; a lone first-line run is deterministic and hides it.
- Fix: seed in the same `eval` call, `srand(<s>);<input>`, and take the last value of the printed sequence
  (`seeded` in crates/cas-giac/tests/optimization.rs; same parsing as `last` in tests/all_trig_solutions.rs).
  A list `[srand(s), cmd][1]` does not work (srand gives no value, list elements are not ordered draws).
- Pick a seed under which every input succeeds (seed 0 failed one input, 42 none) and check it over shuffled orders.
