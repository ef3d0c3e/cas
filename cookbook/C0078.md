# A CI test job that never ends: cancel the run, then diff the finished tests against the last green run

- GitHub serves a job's log only once the job ends; a hung `cargo test` keeps it in_progress for hours (default timeout 360 min) and `gh api …/jobs/<id>/logs` returns nothing useful.
- `gh run cancel <run>`; after ~30 s `gh api repos/<o>/<r>/actions/jobs/<job>/logs` returns the partial log (libtest's `has been running for over 60 seconds` lines included).
- Libtest prints a failing test's panic only in the end summary, so a killed binary loses every FAILED test's message: get the hang fixed first; the next run shows them.
- Find the hung test: collect `test <name> ... ok|FAILED|ignored` from the same binary's section of the last green run's log and of this one; the name missing from this one is the hang (1.7/T2: `native::simplify::tests::shared_subexpressions`, a 2^80-leaf DAG, after two builtins were added). Script: regex `test (\S+) \.\.\. (ok|FAILED|ignored)`, stop the green log at that binary's `test result:` line.
- A test in an untouched module that hangs or fails right after builtins are added: suspect symbol renumbering (C0058).
