# Porting giac's branch and bound: Gomory cuts on an exact simplex

When: porting lpsolve.cc's B&B (or any MIP search) onto our rational simplex.

- Cuts without an incremental tableau: take the optimal tableau's rows with an integer basic column and fractional rhs, build the GMI coefficients over nonbasic columns, substitute each slack by its row (`s = b - a·x`), add the cut as a `≥` row and re-solve from scratch. Simple, exact; costs a few pivots.
- Integer columns = columns of integer variables whose shift end is an integer (free `x = x⁺ − x⁻`: both); every slack continuous (weaker, always valid).
- giac bug: it integralizes the cut's coefficients but keeps the right side 1 (lpsolve.cc:762-786), a different inequality when the scale is not 1. Add the cut itself; use the integralized form only for the 1e6 magnitude filter.
- giac's rounding heuristic ignores variable bounds (violated_constraints checks rows only): count the program's own bounds too, or an infeasible incumbent can come back.
- Verify the port with a Python twin (same ties, same pivot rule) against brute force over every option combination before the Rust (720 combos, 0 mismatches) and use it to predict limit rows (`[]` vs incumbent) for the oracle.
- Fixed ties where giac draws `_rand`: oldest active node, lowest variable index.
