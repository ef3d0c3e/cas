# C — Triage a fuzz numeric mismatch: check the oracle side before the engine

A fuzz target that checks a symbolic answer against a numeric one (NIntegrate, a substitution) can itself be wrong.
Before briefing an engine fix, work the failing case by hand from the panic message: if the symbolic answer is right
and its value matches, the harness is at fault.

Cases from 1.3/T11 (fuzz/fuzz_targets/fourier_transforms.rs):
- Harness: f complex (`e^(i k x)` modulation) while the check took only the real part of each NIntegrate; with
  I1 = ∫f cos, I2 = -∫f sin both complex, F = I1 + i I2, so Re F = Re I1 - Im I2, Im F = Im I1 + Re I2 (f3fab1f).
- Engine: a formula valid for a real pole only (the principal value of 1/(p x + q), steps and signs at -q/p) fired
  for a complex one (q/p = -i) in the inverse by duality; it needs `Im(q/p) = 0` (c010b79).
