# C0021 — libgiac PARI failures abort the process after the call: test risky rows alone
tags: giac,oracle,pari,crash,libgiac · date: 2026-11-23 · phase/task: 1.3/T2 · origin: CAS-551 is_prime

libgiac's PARI calls can kill the process after the call returned (1.3/T2.c2, 2026-11-23).
- is_prime(2^607-1) overflows PARI's stack and aborts; a 62-digit prime prints "Error in PARI subsystem" and the
  process dies afterwards; is_prime(-2147483659,1) crashes. caseval's per-line child process (C0018) shows them as
  `<stderr>`, but a crash after a seemingly normal answer would still kill the shared oracle test binary on CI.
- Before adding a giac row for big-integer or PARI-backed inputs, run it alone in a scratch binary calling
  `Giac::eval` (crates/cas-giac) and check the process exits cleanly; otherwise make it an ours-only row.
