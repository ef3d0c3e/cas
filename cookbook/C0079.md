# Walks over an Expr keep a seen set; a may_contain fast path only hides a tree walk

- Exprs are DAGs: `f[e, e]` nested 80 deep has 2^80 leaves and 81 distinct nodes. A recursive or explicit-stack walk with no memo visits every occurrence.
- Such a walk often sits behind a bloom fast path, `if !e.may_contain(S) { return }` (expr.rs:271), and stays cheap until a symbol's bit collides with S's.
- Adding builtins shifts every user symbol's id, and so its bit (`symbol_bit`, expr.rs:303; C0058). In 1.7/T2, two new builtins gave the test's user symbol `f` Binomial's bit 61. factorials.rs's `classes` (explicit stack, no memo) then ran 2^80 pops, and `simplify::tests::shared_subexpressions` hung CI (C0078).
- Fix the walk, never the bits: a `HashSet<&Expr>` of nodes already popped (factorials.rs `classes`, T2.c4 2488b71), or the traverse.rs helpers, which run once per distinct subexpression.
- To check a suspected collision by hand, recompute `symbol_bit` from builtin.rs's order at both commits (script .run/1.7/T2/c4/bits.py, scratch).
- Not yet checked for the same flaw: simplify/trigonometric.rs's helpers (`tan_out`, `pythagorean`, `tan_in`), reached when a symbol lands on Sin, Cos or Tan's bit.
