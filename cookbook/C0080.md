# Sorting mixed exact and decimal values: one comparator kind for the whole slice

Problem: a native sorts a list whose entries may be rationals or decimal balls (fuzz feeds both). A comparator that
uses `Rational::cmp` when both sides are exact and f64 otherwise is not a total order (an exact pair and a decimal
pair disagree through rounding); Rust's `sort_by` may panic ("user-provided comparison function does not correctly
implement a total order") on such input.

Move: decide once for the slice. Every value exact → sort by `Rational::cmp`; otherwise convert every value with
`to_f64` and sort by `f64::total_cmp`. Never mix inside one comparator.

Where: T3.c1 empirical cdf/icdf (crates/cas-core/src/native/statistics/distributions/tails.rs). Related: C0028.
