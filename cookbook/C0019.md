# C0019 — Fuzz timeout with no limit hit: bound the product of limits
tags: fuzz,timeout,limits,polynomial,power · date: 2026-11-23 · phase/task: 1.2/T11 · origin: CAS-547

Fuzz timeout in a polynomial builtin where no limit fired (CAS-547, T11.c1, 2026-11-23).
- Check what each limit misses, not only whether one was hit: separate bounds (terms per product, bits per
  coefficient) can each pass while their product is huge. `(1+x^2/4)^46656`: 46657 terms (< 1e6) × ~140k bits
  (< 2^24) ≈ 800 MB in `Converter::pow` (crates/cas-core/src/poly.rs). Fix: bound terms × coefficient words by
  `Limits::terms` before computing (`power_terms`: least of several estimates incl. multinomial C(e+t-1,t-1), so a
  one-term `x^(10^7)` stays allowed).
- Find it fast: C0002 step 2 repro crate timing each eval + 2-3 gdb samples names the hot path in minutes; time the
  size ladder (n=2000 0.47 s, 4000 5.2 s, 8000 60 s) to see the growth.
- Predates-phase check: decode the timeout input of an earlier run's same-target job (e.g. a cancelled Fuzz run
  that still finished that job); the same expression settles it.
