# Locating an eval fuzz panic and replaying it locally

Crash artifact (not a hang): `gh run download <run> -n fuzz-artifacts-eval-<run> -D .run/<phase>/crash`.
1. Find the panicking caller without spending the one allowed fuzz replay: the C0002 scratch crate (copy
   `fuzz/fuzz_targets/eval.rs`, drop `#![no_main]`/`fuzz_target!`, a `main` that reads the file, `.leak()`s it,
   runs `int_in_range(16..=128)`, `context`, `expr(u, 5, Room{..})`, prints `{e:?}`, then `ctx.eval` on a thread
   with a large stack) built `--release` with `debug = 1`; `RUST_BACKTRACE=1` names the caller file:line, and
   the printed expression is full form, parseable by `Expr::parse_full_form`, so the regression test can use it.
   Splice the `main` in by cutting from `fuzz_target!(` to the `/// The checks on one input.` comment (cutting at
   the first `});` leaves the thread scope's closing braces behind).
2. cargo-fuzz is not installed on the dev machine: `cargo install --locked --root .run/<phase>/tools cargo-fuzz`,
   then from `fuzz/`: `PATH=<repo>/.run/<phase>/tools/bin:$PATH ../scripts/capped.sh cargo fuzz run -O eval <file>`.
   Green = `Executed <file> in N ms`, exit 0.
Example: T1 1.1, CAS-525 (`FromContinuedFraction[{-2,-1,0,1}]` → `Rational::new(p, 0)`).
