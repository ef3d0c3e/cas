# A new builtin can capture a bare word other natives match by name

When a giac entry's name is also a word existing natives read as an option or distribution name
(`name() == "<word>"`, e.g. `randvar(multinomial,...)`, `randvector(..,multinomial,..)`), adding it to
en.txt makes the word lower to the new builtin symbol and the old match silently fails (1.8 T4.c1:
four random_variables tests red, CI 45753608719).
- Before adding a builtin, `grep -rn '"<word>"' crates/cas-core/src crates/cas-lang/src`.
- Fix: the matcher also accepts the new symbol (`is_multinomial` accepts `Symbol::MULTINOMIAL_PROBABILITY`).
