# C0066 — A Context input a cached result depends on: a State field set via state_mut
tags: context,cache,stamps,state-id,hook,settings · date: 2026-11-25 · phase/task: 1.6/T3 · origin: T3.c1 725956e

# Anything a result depends on goes in Context's State, set through state_mut

Problem: evaluation stamps fixpoints with the context's state id (node.rs eval_stamp; context.rs `stamp`).
A value stored on `Context` outside `State` (like `random`, `interrupt`) changes no id, so an expression
stamped as a fixpoint before the change is reused after it: e.g. `ToString[x]` left as is with no
language hook would stay a fixpoint after a hook is installed.

Move: put the field in `struct State` (context.rs) and give it a setter through `state_mut()`: a fresh
`StateId` and a fresh warned table. Clones share it, scopes (`assuming`, `numeric`) inherit it.
Only state that must not change ids (the random generator: drawing would invalidate every stamp)
belongs outside.

Seen: 1.6/T3.c1 (725956e) `Context::set_language` (CAS-614); the settings Digits, all_trig_solutions,
with_sqrt follow the same rule (C0011).
