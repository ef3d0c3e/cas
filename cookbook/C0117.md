# A native's nested Context::eval gets fresh limits: 2^depth on nested arguments

A native that runs `Context::eval` (directly, or through `approximation`, native/numeric.rs:290-293) on an argument
that was already evaluated gets a fresh `self.limits()` (eval.rs:1049-1052): no recursion or iteration limit counts
the nesting. When that argument can hold the same head, each level evaluates its inner level twice, so cost is
2^depth. CAS-649: `MarkovChain[m, eps]` checks `eps` with `real` -> `approximation` (markov.rs:273-281); `eps`
nested 25 deep took ~20 s and doubled per level; a fuzz rule built the depth up to the iteration limit.
Recognise it: gdb backtraces (C0002) of 300 frames repeating `native -> approximation -> Context::eval -> ... ->
native`; timing that doubles per nesting level, while HoldRest on the wrapper makes it instant.
Avoid it: test an evaluated argument structurally (`to_rational`, `view()`), or run the nested evaluation on the
caller's remaining budget; grep `approximation(`/`.eval(` on arguments when adding a native.
Diagnose: scratch decode crate (C0002 step 2) with a second argv for a full-form expression and env vars for one
rule; time nesting depths 16/20/24 to see the doubling.
