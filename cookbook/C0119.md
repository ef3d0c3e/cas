# Pre-CI sweep batch: check giac against an exact reference, and guard by the drawn structure

Problem: a pre-CI batch (C0114) that only looks for giac errors and floats misses a wrong giac answer.
`lpsolve(…,maximize)` with 3 variables and ≥1 constraint gave a wrong optimum in 67/723 draws
(`lpsolve(4*x+3*y-4*z,[x+z<=1,-2*y<=9],…,assume=integer,maximize)` gives 8, the optimum is 11).
CI caught it as `lpsolve(x,[-y+z<=0],x=0..1,y=0..1,z=0..1,maximize)[0]` (giac 0, ours 1).
Fix: in the Python mirror of the generator, compute an exact reference (vertex enumeration with
Fractions; brute force over the lattice for `assume=integer`). Compare giac with it across the
batch, and find the departure class from the mismatches (2.1 T4.c1, 6000 draws).
Also from the same batches:
- giac lpsolve gives Bad Argument Type when a box variable appears in neither the objective nor a
  constraint, and when a constraint has all-zero coefficients. Generate around the second;
  skip the first.
- markov(M) is exact in giac only when there is no absorbing state and either one recurrent class
  or no transient state. An absorbing state prints `1.0`; ≥2 classes with a transient state give
  iterated absorption values like `2199023255551/2199023255552`. Its hang class (transient
  states, ≥2 classes, a periodic class) lies inside the second skip. Compute the guard from the
  drawn matrix's reachability (markov.rs `exact_in_giac`): 6994/6994 draws matched.
