# Iterated user steps on balls: take the midpoint, or the radius compounds

Context: a native feeding a user function's answer back into the same function (simulated annealing's step
`(x,m)->rand(x-m,x+m)`, any fixed-point or Markov-chain loop).

- Mechanism: both bounds of `Random[x-m, x+m]` carry x's radius r; ball arithmetic treats them as independent, so the
  draw's radius is about r(1+2u), ×~1.9 per accepted step. After enough steps `sin(20x)`'s ball covers [-1,1], the
  cost's midpoint is meaningless, and the search freezes at an early point (CI 45347780940: 2 of 3 seeds missed 1e-3).
- Symptom: N[...] of the cost warns `InputLimited` (numeric.rs:262) once per step (warning count = step count).
- Fix: replace each ball in the step's value by `Ball::exact(mid)` before reuse (GSL works on doubles):
  simulated_annealing.rs `points()`. Don't change Random: its bounds' dependency is invisible to it.
- Prototype check: model the radius in the Python prototype (1.5/T7's siman_radius.py, scratch, not kept): 5/8 seeds miss with
  radii, 8/8 hit with midpoints.
