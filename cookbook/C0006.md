# Numeric oracle tests: closed form first, oracle only inside its own error

When a test compares a numeric builtin with giac (or any double-precision oracle) and fails, check the oracle against a
closed form before blaming ours. giac's fixed-step solvers (`bvpsolve`, `odesolve`) carry discretisation error that can
exceed the test tolerance on coarse grids.

- Check small grids against the closed form, evaluated in our CAS: `evalf([[x_k, y(x_k)], …])` built in the test
  (see `grid` in crates/cas-giac/tests/ndsolve.rs).
- Compare with the oracle only at a step where its error is inside the tolerance. Pick the step from the oracle's
  observed error at two steps (its manual's example, the failing CI log's values), via its order (`bvpsolve`: about
  `h⁴`, 4·10⁻² at h = 1/2, 4·10⁻⁵ at h = 1/10), not by trial runs: tests run only on CI.
- Record the coarse-grid disagreement as a departure (polynomials.rs `departures` pattern). Numeric answers are
  checked within the tolerance (`close_points`), not by printed string equality. The CI failure message's Debug
  output gives giac's doubles as hex balls; decode them with `float.fromhex`.
- Keep the tolerance; the fix is in what is compared.
