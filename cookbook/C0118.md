# Nesting tests for an approximation guard: the inner call must stay held at every level

A CAS-650 nesting test (30 levels, head unchanged, < 2 s, as markov/tests.rs:287) proves nothing unless each level
reaches the guarded `approximation(` with the inner call held. Two traps:
- A native that always returns a result once past the site (JordanMatrix: `plane` at echelon.rs:214, then a matrix)
  never nests in itself; nest it inside another native that stays held on a held entry instead
  (`JacobiLinearSolve[{{JordanMatrix[{{1,0},{1,inner}}]}}, {1}, 10^-12]`, matrix/tests.rs `nested_eigenvalue`).
- An earlier check may answer first: Cholesky's symmetry check hits `is_zero` (decompose.rs:158) before the pivot's
  `positive` (:312), so each site needs its own shape ({{1,0},{inner,1}} vs {{inner}}).
Guard choice: take the site's existing no-value branch (what a non-Ball approximation gives today), e.g. `is_zero`
keeps `Some(false)`, not `None`, else Cholesky's "not symmetric" turns undecided.
Each test's doc comment says which site it reaches and why the inner call stays held; R74 means no local run proves it.
- Fresh variable per level (x1, x2, …) so the outer substitution never rewrites the held inner call (T3.c1 7937c2a: Limit, Series, Sum tests).
