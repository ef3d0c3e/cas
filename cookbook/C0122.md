# Oracle red with no related change: check the giac version first

CI's `oracle` job runs in `debian:sid` and installs `libgiac0t64` unpinned (.github/workflows/ci.yml:58-61).
When sid upgrades giac, oracle rows break with no change on our side.
- First check: grep the oracle job log for `Unpacking libgiac0t64` and compare it with the last green run:
  `gh api repos/ef3d0c3e/cas/actions/jobs/<id>/logs | grep "Unpacking libgiac0t64"`.
- 2026-11-27: 2.0.0.21+dfsg2-3+b1 (green, 46063574633) became 2.1.0.1+dfsg2-1 (red, 46069824120).
  It broke mathml.rs:377 `mathml_documents` (giac now writes `<mo>(</mo>`, not `<mfenced>`) and
  derivatives.rs:227 `random_n_deriv`.
- A re-run does not help. Pin the package version, or open a task to move to the new giac.
