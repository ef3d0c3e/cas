# C0001 — Performance A/B on CI with the Workload workflow
tags: benchmarks,ci,workload,gh · date: 2026-11-22 · phase/task: - · origin: gen3.2 memory benchmarks-on-ci.md

Workloads (ignored `*_workload` tests) run only through `.github/workflows/workload.yml`, never locally:
`gh workflow run workload.yml -f test=<path> -f runs='ENV=a;ENV=b' [-f base=<commit>]` (the refs must be on GitHub).
Reports best-of-3 wall time (ms) and max RSS; `base` builds an older commit on the same runner for a fair A/B.
Read the table from the job log: `gh api repos/ef3d0c3e/cas/actions/jobs/<id>/logs`, lines starting `| `.
- The runner has no `perf` (instruction counts show `-`): compare times only.
- Runner ≈ 4/3 of dev-machine time (Fateman 9.8 s local vs 12.62 s runner): scale older local or giac figures in docs.
- Methods within one commit (`CAS_POLY_GCD=sparse:modular:12` vs `sparse:zippel:12`) need no `base`.
