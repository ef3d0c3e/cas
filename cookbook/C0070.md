# C0070 — Settings with a bare value: name() goes through the session, not a native
tags: settings,session,eval,head,native · date: 2026-11-25 · phase/task: 1.6/T6 · origin: T6.c1 settings

# A setting's call form name() cannot be a native when its bare name has a value

eval.rs `parts` evaluates a call's head first; a setting's bare name has a value through native.rs `value()`
(Digits, approx_mode, …), so `ApproxMode[]` becomes `0[]` before any native for ApproxMode runs.

- Answer `name()` and `name(v)` in a session execute arm (statement level only); nested `approx_mode()+1` gives `0()+1`,
  as `Digits()` always did.
- Outside a session (cas-giac `ours`, `Context::eval`) `gbasis_max_pairs(4096)` evaluates to `32768(4096)`: settings
  oracle rows run in a `cas_lang::Session` (tests/settings.rs).
- A setting with no bare value (cas_setup) can keep a native for its zero-argument form.
