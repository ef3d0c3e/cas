# giac's row reductions: algorithm numbers, pivot order, where `_ref` lives

When matching giac's `ref`, `rref(…, keep_pivot)` or any `mrref` user:
- `_ref` is in src/ti89.cc (:2049 in 2.0.0.21), not vecteur.cc. It passes algorithm 1 = `RREF_GUESS` (vecteur.h:268-269; `RREF_GAUSS_JORDAN` = 0): each row is cleared of denominators and divided by its content, then reduced fraction-free (Bareiss, exact division by the previous pivot).
- Exact pivot choice: `betterpivot` → `islesscomplexthan` (gen.cc:9948): smaller absolute value wins; of two opposites the positive wins; otherwise the first. Floats: larger abs.
- `_rref` with `keep_pivot` skips `mdividebypivot`; with ≥ as many columns as rows it eliminates below, then back-substitutes so every pivot is the last pivot d.
- Prove the port with a Python `fractions` prototype (C0009): T9.c1 matched 72/72 probes and 150/150 random matrices (.run/1.2/T9/proto.py, scratch).
- egvl (giac 2.0.0): J's eigenvalues sorted real part descending, imaginary ascending (-i before i); an input already in Jordan form comes back unchanged.
