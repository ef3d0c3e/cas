# Pin a Debian package to an exact version from snapshot.debian.org

For a container on debian:sid (or any suite) where `apt-get install pkg=ver` stops working once the suite moves on.
- Look up the file's hash: `curl -s "https://snapshot.debian.org/mr/binary/<pkg>/<ver, + as %2B>/binfiles?fileinfo=1"`.
  It gives the sha1 per architecture, `first_seen` (a timestamp) and the pool `path`.
- URL: `https://snapshot.debian.org/archive/debian/<first_seen>/<path>/<name>`.
- In CI: `curl -fsSL --retry 5 --retry-all-errors -o /tmp/x.deb "$URL"`, `echo "$SHA1  /tmp/x.deb" | sha1sum -c -`,
  `apt-get install -y ./x.deb` (its library dependencies come from the current suite), then
  `test "$(dpkg-query -W -f='${Version}' <pkg>)" = "$VER"` under `set -eux`, so a mismatch stops the job.
- Example: .github/workflows/ci.yml oracle job (libgiac0t64 2.0.0.21+dfsg2-3+b1). It breaks only when sid drops a
  library soname the old .deb depends on (libpari-gmp-tls10, libntl45, libgsl28, ...). The install then fails, so
  the job stops.
