# Porting GSL routines giac calls: fetch the tarball, exact literals, ctypes as the reference

giac hands some commands to GSL (dwt/idwt → gsl_wavelet*, emd → gsl_interp_cspline). giac's source alone does not pin the numbers.

- Fetch once: `curl -sSfL -o .run/<phase>/T<n>/dl/gsl.tar.gz https://ftp.gnu.org/gnu/gsl/gsl-2.7.1.tar.gz`, then `tar xzf` only the dirs needed (`wavelet`, `interpolation`, `linalg/tridiag.c`). GPL-3 like cas: port, cite file:function.
- Transcribe GSL's C coefficient arrays by script into Rust decimal strings read as exact rationals; the ball then encloses the transform *with GSL's filters* (round trips are ~1e-28, not exact: GSL's literals are not exactly orthonormal). Keep pointer offsets (bspline.c's centred tables) as in GSL.
- Haar exact on exact data: each entry a + b·sqrt(2), a, b rational (T9.c1).
- giac's 2.2e-16 entries are double noise: the exact transform gives ~3e-29; oracle rows go through check_near (C0006).
- The system libgsl answers the prototype bit for bit through Python ctypes (T9.c2's gsl_ctypes.py): use it as the reference for f64 ports (emd's cspline). It runs GSL, not our code (R74 allows it).
- giac's option `centre` in the source is reached by the bare word `center` (bare `centre` → "Invalid argument 2").
