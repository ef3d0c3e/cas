# Bit-exact ports of giac's buffer quirks and C library folds

When: porting a giac (C++) numeric loop that must match libgiac's printed answers code for code.

- `std::pow(x, 2)` is folded by gcc to `x*x`: port it as `k*k`, never `powi`/`powf` (giac mix's cos² fades, signalprocessing.cc:1178-1180).
- `pow(1, NaN) = 1`, every other `pow(x, NaN)` is NaN: a NaN exponent leaves only the samples whose base is exactly 1 (splice's last crossfade sample when the similarity is NaN, T8 probe1:36-39).
- giac buffers that are bounds-checked on access (`get_sample` reads 0, `set_sample` drops OOB writes) but filled by `memcpy` may overflow: port the visible answer with bounded copies (splice with a short second clip, :1203-1204), and give the row that reads past a buffer no oracle row (it can vary between runs, C0021).
- A flag overwritten per sample (`clipping = s > 1 || s < -1`) reports only the last sample: say so in a departure row when ours reports any sample.
- Prove the port with a Python prototype in plain f64 and in 47-bit doubles (C0088) before the Rust.
