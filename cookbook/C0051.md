# Remez exchange: giac's one-peak-per-zero-interval step fails; use a full exchange

Remez's exchange as giac optimization.cc:_minimax does it (one zero of e between consecutive reference points,
then golden section between consecutive zeros, endpoints swapped in if larger) fails in two ways (T7.c1, 2026-11-23):
- abs(x) degree 2 on [-1,1]: the Chebyshev start interpolates (E=0), then the reference settles on points that do not
  alternate in sign; giac answers 0.2134, the best is 1/8 (x^2+1/8).
- min(1/cosh(3 sin x), sin(9x/10)) degree 30 on [-3,4]: diverges in our prototype (emax 2e4); giac stops at 0.0947,
  the best is 0.0319 (checked by 200001-point sampling).
Fix (crates/cas-core/src/native/minimax.rs): full exchange. Sample e on 16 steps between consecutive points, one point
per run of one sign refined by golden section, merge, pad with an interval end if short, keep the window of N points
with the largest |e|. Run in f64 in the Chebyshev basis on [-1,1], not monomials (degree 30 on [-3,4]).
Also: do one more iteration after the stop rule fires (x^3 degree 2 gave 0.75000000439 without it); an f that is already
p/q has too few sign runs: treat max|e| <= 64 eps max|f| as converged. Prototypes: .run/1.4/t7/remez.py (scratch).
Consequence for oracle rows: giac's unconverged minimax errors can be far above the best (x*exp(-x) [5,3] rand=30:
giac 2.56e-4, best 4.36e-5): compare only when ours is within 2% below giac's, else a departure row.
