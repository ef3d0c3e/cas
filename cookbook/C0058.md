# Expr::may_contain is a bloom filter: never assert its negation

- `Expr::may_contain(s)` (crates/cas-core/src/expr.rs:271) tests one bit of a per-expression symbol mask (`symbol_bit`); bits collide.
- `!e.may_contain(S)` in a test passes only while no symbol in `e` shares S's bit. Adding builtins renumbers symbols and moves the bits: 1.5/T4.c1 (14 new builtins) broke `trigonometric_interpolation`'s `!found.may_contain(Symbol::PI)` with no change to interpolation.
- Prove absence with `e.free_of(&Expr::from(S))` (traverse.rs:150; it uses the mask as a fast path, then walks).
- `may_contain` stays fine as a fast negative filter in code (skip work when false), never as a proof of absence.
- A test failure in an untouched module right after builtins are added: check bloom-mask assertions first.
