# Oracle value comparison: Exp[u] vs E^u, giac's <>, and Solve on quotients

From CAS-581..583 (T7.c1/c3, 2026-11-23).
- giac prints not-equal as `<>`; our parser reads only `!=`. crates/cas-giac/src/format.rs `for_language` now maps it
  (ebe295f); before that every domain row with `<>` failed as Unreadable on CI.
- Comparing cells by `Simplify[a - b] == 0` leaves `exp(-1) - 1/exp(1)` undecided: rewrite `Exp[u]` as `E^u` on both
  sides before simplifying (tests/function_study.rs tables check).
- Our `Solve` stays on a quotient (`ln(x)/x == 0`): solve `Numerator[Together[g]]` when only zeros matter.
- `-Infinity != -Sqrt[2]` stays undecided: test an infinite point against the closure, not by Unequal.
- giac's conditions keep the integer-primitive form of the factor (`6x^2-1>=0`, not monic `x^2-1/6`); oracle rows
  compare values, so a monic rewrite is a failure, not an equivalence.
