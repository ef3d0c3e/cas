# Matching giac's exact output: port from its source, prove with a Python prototype

When a giac builtin's answer depends on implementation details (rounding, scaling, interval ends), probes alone
do not pin the formula (T4: sturmseq's 3rd remainder 49 vs the textbook 441; VAS(x-100) = [[0,204]]).

- Fetch the matching source once: `curl -sSfL -o .run/<phase>/T<n>/src/<f> https://sources.debian.org/data/main/g/giac/2.0.0.21+dfsg2-3/src/<f>`
  (same build as local xcas and CI). Find the function: `grep -n "_<name>_s\|gen _<name>" *.cc`; giac files seen:
  csturm.cc (VAS, LMQ, complexroot, rationalroot), alg_ext.cc (sturm wrapper), poly.h (Tsturm_seq), gausspol.cc.
- giac is GPL-3 like cas: port the algorithm in our own code, cite the file:function in the chapter.
- Since tests run only on CI, prototype the port in Python with `fractions` (scratch in .run/) and check it against
  every probe answer before the Rust; the Rust follows the prototype step by step. Found 0 mismatches in T4 this way
  (20 VAS, 21 posubLMQ, 13 poslbdLMQ, 11 sequences).
- giac often uses doubles (posubLMQ = ceil(65·LMQ/64)); ours exact, so note the edge in the chapter.
