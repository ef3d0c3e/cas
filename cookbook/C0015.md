# giac's command line and libgiac (the oracle) can print different answers

Probe with `giac < file` is fast, but the oracle tests call libgiac's `caseval` (crates/cas-giac/src/lib.rs `Giac::eval`), and the two differ on some inputs:
- `rootof([1,0])`: CLI `infinity`, libgiac `undef` (1.2/T6).
- errors: CLI prints a quoted string, libgiac `GIAC_ERROR: <msg>` (C0007); the exact whitespace (a space before `\n`) matters in departure rows.
- `poly1[1,2]` in CLI output reads back as a list through `format::for_language`, so a row that looked like a departure may agree.

Move: probe with the CLI to plan, then before writing departure rows run the candidate inputs once through `Giac::eval`/`agrees` (a scratch probe under `.run/<phase>/`, removed after) and copy giac's text from that output.

Also (1.2/T6 bezoutian): det(Bezout matrix of f, g) = ±lc(f)^(deg f − deg g)·Res(f, g), not ±Res, when deg f > deg g; a det = resultant identity test needs equal degrees or the lc factor.
