# giac garbage answers change between runs: record the reason, never the text

Context: departure rows copy libgiac's printed answer (C0007, C0015, C0018). Where giac computes from
uninitialised doubles, its text is not stable: `area(a*x,x=0..1,2,rombergt)` printed `6.10593455919e+306` in
caseval.py and `4.81721418985e+306` on CI (CAS-589, 1.4/T2; giac's rombergt reads `_DOUBLE_val` of a symbolic gen).

Move: for an answer that is garbage (huge, meaningless, from a non-double gen read as a double), keep the departure
row but compare only ours; write the reason and an example value in the comment and the README, not as a key.

Check: before recording a suspicious departure text, run the same input twice through caseval.py (separate
children); a changed answer is garbage, not giac's convention.
