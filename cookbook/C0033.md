# Reading giac's calculus answers back, and symbols natives create

- giac prints second derivatives `diff(y(x),x,2)`; our language reads that as d/dx then d/d2. Since 1.8/T1 (CAS-636, rule D/nth) ours reads it as the second derivative too: no rewrite needed.
  Rewrite `diff(f,x,n)` to `diff(f,x,x,..)` in giac's text before `ours()` (oracle helper in
  crates/cas-giac/tests/calculus_tools.rs, 1.3 T6.c3).
- A native that creates a capitalised user-visible symbol (giac's constants `K_0`) names it
  `$K_0` (cas-lang `escape_name`); a plain `K_0` fails to print and does not match the user's
  `K_0`. Number per call, skipping names already in the input (native/dsolve/variational.rs).
- giac's numbered constants come from process-global counters (euler_lagrange `cnst_count`,
  optimization.cc:7877): in the shared oracle renumber giac's K_n in order of appearance.
- Our `Together` is not idempotent on radicals: `(u^2-(1+u^2))/sqrt(1+u^2)` needs `Simplify`
  (or a second pass) to stand in for giac's simp+radsimp.
- giac's sequence answers `a,b` have no surface in our language: split giac's text at its
  top-level comma and compare each part.
