# C0125 — Max(1,|b|) stays unevaluated on a ball straddling 1: split tolerance claims
tags: giac,oracle,tolerance,ball,max,less,near · date: 2026-11-28 · phase/task: 2.2/T1 · origin: CAS-662 near

A relative-tolerance claim `Less(gap, t*Max(1, Abs(N(b))))` is undecided when giac's value `b` reads back as a ball
straddling 1 (any exact 1 computed in doubles): `extremum` (cas-core native/rounding.rs) drops an argument only when
`real_sign` of the difference is decided, so `Max(1, b)` stays unevaluated, `Less` against it stays unevaluated, and a
test that wants `True` fails on a correct answer. Symptom: a random oracle test fails only at points where the exact
value is ±1 (2.2 T1, CAS-662: nDeriv at x=3/10).
Fix without loosening: `|a-b| < t*max(1,|b|)` iff `|a-b| < t` or `|a-b| < t*|b|`; evaluate the two `Less` claims
separately (crates/cas-giac/tests/derivatives.rs `near`). `1+|b|` is decided too but loosens the bound up to 2x.
Test the checker on a straddling ball: `ours("(0.1+0.2)/0.3")` is a ball around 1 (unit test `near_decides_around_one`).
