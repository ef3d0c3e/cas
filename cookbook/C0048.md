# Recurrences over Expr on symbolic inputs: bound the point count, not only the work

Found at T4.c3 (2026-11-23, CAS-595 numdiff).
- A recurrence evaluated through `ev.eval` (divided differences, Taylor coefficients of a Newton form, barycentric
  weights) stays cheap on numbers, but with symbolic abscissas or x0 the products stay unexpanded and nest: each
  coefficient's tree grows about as C(n,k), so an n·M work bound alone does not stop a fuzz timeout.
- Fix: a numeric fast path (Rational, or decimals) for the full point limit, and a small point cap (numdiff: 12) when
  any abscissa or x0 is not a number (crates/cas-core/src/native/interpolation/derivatives.rs).
