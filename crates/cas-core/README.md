# cas-core

Hash-consed symbolic expressions for the CAS engine. The design is in Lific page `CAS-DOC-3`.

## Layout

| Module | Contents |
|---|---|
| `expr` | `Expr`, the 16-byte handle: a `Symbol` or an `i64` inline, or a shared interned node. Equality is O(1) (value or address) because every value has one representation. `Expr::apply`, `Expr::string`, `From<Symbol>`, `From<i64>`, `From<Integer>` and `From<Rational>` (re-exported from cas-num): an integer that fits `i64` is always inline, a larger one an `Integer` node, a non-integer a `Rational` node, and a rational with denominator 1 an integer, so each number has one form. `view()` and accessors (`as_i64`, `to_integer`, `to_rational`, `is_number`); cached metadata (`depth`, `size`, `may_contain` Bloom test, `is_numeric`, `has_pattern`); a structural hash. |
| `build` | The builder, the public way to construct expressions from Rust: `+ - * /` and unary `-` on `Expr`, `&Expr`, `Symbol` and `i64`, the assignment operators, `pow`, `Sum`/`Product` over iterators, `Expr::call`, `symbols`, `list` and `sin`/`cos`/…. Context-free: builtin `Flat` heads are flattened (iteratively) and `Orderless` heads sorted; nothing is evaluated (`x + x` stays `Plus[x, x]`). `x - y` is `Plus[x, Times[-1, y]]`, `x / y` is `Times[x, Power[y, -1]]`, and negating a number atom gives the negated literal (`-i64::MIN` is the integer `2^63`). |
| `symbol` | `Symbol`: a permanent `u32` id into a global, append-only name table, which starts with the builtins. |
| `builtin` | The builtin symbols (`Symbol::PLUS`, `Symbol::BLANK`, …): fixed ids `0..COUNT` and fixed attributes, declared in one list. Which heads are pattern constructs. |
| `attributes` | `Attributes`, the attribute bit set (`FLAT`, `ORDERLESS`, `HOLD_ALL`, `NUMERIC_FUNCTION`, …). |
| `context` | `Context`: values, attributes of user symbols, assumptions and limits, copied on write. Clone is O(1); `assuming` returns a child scope. Every state has a globally unique `StateId`, which keys the per-node fixpoint stamp (`is_fixpoint`, `mark_fixpoint`). `eval` is a stub until Rewriting. |
| `order` | The canonical order, `impl Ord for Expr`: numbers (integers of any size and rationals) by value first; products and powers compared as products of powers (factors from the last, then the coefficient), giving `1 + 2 x + x^2 + 2 y + 2 x y + y^2`; then strings, symbols by name (case-insensitive, lowercase first) and applications by head, length and arguments. Independent of ids, hashes and addresses. |
| `print` | Printing. `Debug` and `Expr::full_form` give the unambiguous full form, `Plus[x, Times[2, Power[y, 3]]]`; `Display` gives infix, `x + 2*y^3`. Infix parenthesises only where precedence needs it, subtracts terms with a negative coefficient, makes negative integer exponents a denominator (`x/(y*z^2)`), never lets an operand start with a sign after an operator (`2*(-3)`, `(-3)^2`, `x^(-1)`, `-(-x)`), and keeps `Times[-1, 3]` apart from the integer `-3` (`-1*3`). A rational prints `3/2` (full form too) and binds like a quotient (`x^(1/2)`, `2*(3/4)`, `1/2*x`); `Times[3, Power[2, -1]]` prints `3*2^(-1)` so it cannot be read as the rational. Both printers run on an explicit stack, so any depth prints in constant native stack. |
| `traverse` | Structural traversal, never evaluating. `part`, `Index` and `replace_part` use the `Part` convention (`0` is the head, `i ≥ 1` the arguments). `positions`, `pre_order` and `post_order` visit every occurrence. `distinct`, `symbols`, `contains`/`free_of`, `replace` (top-down), `substitute` (simultaneous literal rules) and `map_bottom_up` visit each distinct subexpression once, memoised by node identity, so they are linear in distinct subexpressions on shared DAGs. Unchanged parts keep their handle. `contains` and `substitute` skip subtrees by their metadata. All of it is iterative. |
| `node` | Interned nodes (integers outside `i64`, non-integer rationals, strings and applications) with their hash and metadata. Dropping releases children iteratively through a per-thread queue, so deep expressions use constant stack. |
| `intern` | The global interner: 64 mutex-protected shards of weak references, looked up with a borrowed key (a hit allocates nothing). A node removes its own entry when dropped, matched by address; shards shrink when sparse. `interner_stats()` reports occupancy. |

## Testing

Unit tests are in `src/tests.rs`. They cover structural equality against a plain tree model (proptest, with big integers and rationals among the leaves), one form per number at the `i64` boundaries whatever the constructor, sharing, entry removal, the builtin table and the `NUMERIC`/`HAS_PATTERN` flags (also against the model), constant-stack drops 10⁶ deep, and concurrent construction, churn and symbol creation. The rare interleavings (full hash collisions, a dead and a live entry for the same contents) are set up deterministically on a private shard. Context tests are in `src/context/tests.rs`: protection, scopes that don't leak, ids unique across threads, and a proptest that a stamp matches only the state that wrote it. Order tests are in `src/order/tests.rs`: polynomial and name examples, independence from creation order, and proptests of antisymmetry, transitivity and `Equal` exactly for equal expressions. Builder tests are in `src/build/tests.rs`: every operand type, constant-stack flattening 10⁵ deep, and proptests that `Plus`/`Times` match a flatten-and-sort model, are idempotent and ignore argument order, and that the operators agree with `Expr::call`. Printing tests are in `src/print/tests.rs`: precedence snapshots (negative numbers, nested unary minus, quotients, big integers and rationals, full-form fallbacks, string escapes), constant-stack printing 10⁵ deep, and proptests. Those parse the infix output back with a strict test parser, which rejects an operand that starts with a sign, and check that printing again gives the same text and the same numeric value. They also check full form against a recursive model. Traversal tests are in `src/traverse/tests.rs`: proptests against recursive models (orders, distinct, positions and parts, `contains`, `symbols`, `replace`, `substitute`, `map_bottom_up`); a 2¹⁰⁰-occurrence DAG on which every closure runs exactly once per distinct subexpression; and chains 10⁵ deep. Tests never `assert_eq!` a large or shared expression, because printing a wrong one can take exponential time. `tests/interner.rs` runs alone in its own process and checks that the whole interner empties and shrinks.
